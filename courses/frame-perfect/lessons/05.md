## Brute force tries every sequence

A **search** here means a program that plays the game from a savestate, tries inputs, and looks for a state that passes a test, such as "Kettle has reached the flag". Kettle has six useful inputs: nothing, left, right, jump, left with jump, and right with jump. Taking one state and trying all six on it is an **expansion**. This course measures a search's work in expansions, because seconds depend on your machine and expansions don't.

The supplied `bruteForce` tries every sequence of one frame, then every sequence of two, and so on, and remembers nothing between tries:

<!-- code-example {"file":"examples/toolkit.mjs","region":"brute","language":"js","title":"Brute force","change":"Study the supplied function in the brute region of work/tas.mjs."} -->
```js {"file":"examples/toolkit.mjs","region":"brute","title":"Brute force","change":"Study the supplied function in the brute region of work/tas.mjs."}
// Tries every input sequence of each length in turn and counts the frames it expands.
export function bruteForce(level, maxDepth, goal = finished) {
  let expanded = 0;
  const tryFrom = (state, depth) => {
    if (depth === 0) return null;
    expanded++;
    for (const input of INPUTS) {
      const next = step(load(state), input);
      if (next.ram[ADDR.DEAD]) continue;
      if (goal(next)) return [input];
      const rest = tryFrom(next, depth - 1);
      if (rest) return [input, ...rest];
    }
    return null;
  };
  for (let depth = 1; depth <= maxDepth; depth++) {
    const inputs = tryFrom(newState(level), depth);
    if (inputs) return { inputs, frames: depth, expanded };
  }
  return { inputs: null, frames: null, expanded };
}

export const finished = (state) => state.ram[ADDR.DONE] !== 0;
```
<!-- /code-example -->

Each try loads a fresh copy of the state, so one branch can't disturb another. The goal below is a marker 12 px right of room 0's start and 8 px above it, which Kettle reaches only by jumping.

## Many sequences, few states

Most of those sequences leave Kettle in a state some other sequence already reached, and from that state the same later inputs play out the same way. A search that recognises such a state can skip it, which is called **de-duplication**.

To recognise a state, the search turns it into a **key**, a string that is equal for two states exactly when they will behave the same whatever inputs follow. So the key keeps every byte the future depends on and nothing else. A missing byte merges states that will behave differently, so the search throws away routes that exist. An extra byte keeps equal states apart, so the search repeats work it has already done.

<!-- code-example {"file":"examples/toolkit.mjs","region":"key","language":"js","title":"The state key","change":"Write stateKey in the key region of work/tas.mjs."} -->
```js {"file":"examples/toolkit.mjs","region":"key","title":"The state key","change":"Write stateKey in the key region of work/tas.mjs."}
// Two states with the same key must behave the same from here on, whatever inputs follow.
// The frame counter is left out (the search knows the depth) and so is the random state, which only
// a bell reads. With withRandom, the random state stays in until the bell has rung.
export function stateKey(state, withRandom = false) {
  const r = state.ram;
  let key = '';
  for (let i = 2; i < 24; i++) {
    const isRandom = i === ADDR.RNG || i === ADDR.RNG + 1;
    if (isRandom && !(withRandom && !r[ADDR.BELL])) continue;
    key += String.fromCharCode(r[i]);
  }
  return key;
}
```
<!-- /code-example -->

The frame counter, bytes 0 and 1, is left out because no rule of the game reads it and the search already knows each state's depth. The random state at 0x0b (address 11) is left out because only a bell reads it: a bell is a tile that, hit from below, drops a block in one of a few places chosen by the random state. Levels 1 and 2 have none; module 7 has one, and for it `withRandom` keeps the random state in the key until the bell rings. Bytes 24 to 31 are always zero, so the loop stops at 23.

## Search once per state

`search` expands states in order of a number called their **priority**. With no estimate the priority is the depth, so it works through every state 1 frame away, then every state 2 frames away, and so on, which is **breadth-first search**. The **frontier**, the states found but not yet expanded, lives in the supplied `BucketQueue`, which keeps, for each priority, the numbers of the nodes waiting there. A node, in the listing below, is one found state with its parent's number, its input and its depth.

<!-- code-example {"file":"examples/toolkit.mjs","region":"search-loop","language":"js","title":"De-duplicated search","change":"Write search in the search region of work/tas.mjs. pathTo below it is supplied."} -->
```js {"file":"examples/toolkit.mjs","region":"search-loop","title":"De-duplicated search","change":"Write search in the search region of work/tas.mjs. pathTo below it is supplied."}
export function search(level, opts = {}) {
  const { goal = finished, heuristic = () => 0, budget = Infinity, version = '1.0', withRandom = false, from = null } = opts;
  const root = from ? load(from) : newState(level, version);
  const nodes = [{ state: root, parent: -1, input: -1, depth: 0 }];
  const best = new Map([[stateKey(root, withRandom), 0]]);
  const queue = new BucketQueue();
  queue.push(heuristic(root), 0);
  let expanded = 0;
  while (queue.size > 0) {
    const id = queue.pop();
    const node = nodes[id];
    if (best.get(stateKey(node.state, withRandom)) < node.depth) continue; // a shorter way here was found later
    if (goal(node.state)) return { inputs: pathTo(nodes, id), frames: node.depth, expanded };
    if (expanded >= budget) return { inputs: null, frames: null, expanded, stopped: 'budget' };
    expanded++;
    for (const input of INPUTS) {
      const state = step(load(node.state), input);
      if (state.ram[ADDR.DEAD]) continue;
      const key = stateKey(state, withRandom), depth = node.depth + 1;
      if (best.has(key) && best.get(key) <= depth) continue;
      best.set(key, depth);
      nodes.push({ state, parent: id, input, depth });
      queue.push(depth + heuristic(state), nodes.length - 1);
    }
  }
  return { inputs: null, frames: null, expanded, stopped: 'exhausted' };
}

function pathTo(nodes, id) {
  const inputs = [];
  for (let n = nodes[id]; n.parent >= 0; n = nodes[n.parent]) inputs.push(n.input);
  return inputs.reverse();
}
```
<!-- /code-example -->

`best` maps each key to the shallowest depth found so far, and a state already reached at that depth or less is never added again. To save memory, each node keeps its parent's number and one input instead of a copy of its whole path. At the end, `pathTo` rebuilds the movie by walking back through those parents. The goal is tested when a state leaves the frontier, not when it's found, so the first goal to leave is a shortest one.

Run the marker script again. Search finds a 9-frame route in 6,197 expansions, 0.51% of brute force's work. The check allows 1%.

## A* search with an estimate

Breadth-first search expands every state at each depth, including the many far from the flag. A **heuristic** is a function that estimates how many frames a state still needs. **A*** search expands states in order of depth plus that estimate, so states that look close to the flag go first. If the estimate never overestimates, A*'s first finishing state is still a shortest one. Every state on a shortest route then has a priority no higher than that route's length, so all of them leave the frontier before any longer finishing state.

The supplied `walkingBound` counts the frames to the flag's column at walking top speed, 1.5 px a frame:

<!-- code-example {"file":"examples/toolkit.mjs","region":"walking-bound","language":"js","title":"The walking bound","change":"Study the supplied heuristic in the search region of work/tas.mjs."} -->
```js {"file":"examples/toolkit.mjs","region":"walking-bound","title":"The walking bound","change":"Study the supplied heuristic in the search region of work/tas.mjs."}
// The fewest frames to reach the flag's column at walking top speed: a lower bound wherever nothing
// moves Kettle faster than 24 sub-pixels a frame.
export function walkingBound(level) {
  const flagX = flagColumn(level) * TILE;
  return (state) => Math.ceil(Math.max(0, flagX - (peek(state, ADDR.X, 'u16') + W - 1)) / 24);
}

export function flagColumn(level) {
  for (let tx = 0; tx < level.w; tx++) for (let ty = 0; ty < level.h; ty++) if (level.tiles[ty][tx] === 'F') return tx;
  throw new Error('this level has no flag');
}
```
<!-- /code-example -->

On level 1 it never overestimates, because nothing there moves Kettle faster than walking speed. Module 6 meets two bugs that can. Both need a belt (a floor tile that carries Kettle along), and level 1 has none.

## What real tools do

People who make tool-assisted runs write search programs, often called bots or brute-forcers, that drive an emulator from savestates. A console's RAM is far bigger than 32 bytes, so they key the search on a hand-picked set of addresses found with a memory watch. That is the choice you made in `stateKey`: leave out an address the future depends on and the search loses routes; keep one it does not need and the search repeats work.
