## Put the operator after its inputs

A **predicate** is a question with a Boolean answer. Here is the question “is this quantity greater than 30?” written as a **postfix** program. Postfix means the operator follows the values it uses.

```js
const over30 = [['load'], ['const', 30], ['gt']];
```

Read it from left to right. A **stack** is a pile where the last item added is the first one removed. Each instruction changes that pile.

![The stack after each instruction of over30. For quantity 46: load leaves 46; const 30 leaves 46 with 30 on top; gt pops 30 as the right operand and 46 as the left, and leaves true. For a missing quantity: load leaves null, const 30 puts 30 on top, and gt leaves false because one operand is null.](figures/stack-walk.svg)

`gt` removes the top item first, so 30 is the right operand of `46 > 30`. It takes both numbers off and puts one Boolean back.

## Build the comparison

Replace the unfinished `evaluate` in `work/runtime.mjs` with this working subset from `examples/threshold.mjs`. Keep the imports and the supplied `interpret` wrapper. `push` adds to the top and `pop` removes from the top. A fresh stack belongs to one call, so an order can never inherit operands from the order before it.

<!-- code-example {"file":"examples/threshold.mjs","region":"one-comparison","language":"js","title":"A stack for one comparison","change":"Replace the unfinished evaluate function with this subset.","focus":[7,8,9]} -->
```js {"file":"examples/threshold.mjs","region":"one-comparison","title":"A stack for one comparison","change":"Replace the unfinished evaluate function with this subset.","focus":[7,8,9]}
function evaluate(program, value) {
  const stack = [];
  for (const [op, literal] of program) {
    if (op === 'load') stack.push(value);
    if (op === 'const') stack.push(literal);
    if (op === 'gt') {
      const right = stack.pop();
      const left = stack.pop();
      stack.push(left !== null && right !== null && left > right);
    }
  }
  return stack.pop();
}
```

Run both instruction orders against your own function.

```sh

JS
```

The first row prints `29 false true`. The second prints two false answers because both comparisons are strict. At 31, the columns exchange answers. Both are false on the last row. Removing the explicit null check would allow JavaScript to convert null to zero in a numeric comparison. Try that edit on the reversed program, inspect the last row, then restore the check.

## Give the language its other two operations

Add `eq` and `and` inside the loop. For `eq`, pop two numbers, push false if either operand is null, otherwise push their strict equality. For `and`, pop two Booleans and push their conjunction. Pop the two values in separate statements before evaluating the conjunction. JavaScript can skip the right side of `&&`. A skipped `pop()` would leave a stale value in the stack. You may share the two pops across all three binary operators.

Read `validateProgram` in `lib/program.mjs`. It runs a stack of type names before any row is evaluated. `load` and `const` produce numbers, `gt` and `eq` produce Booleans, and `and` needs two Booleans. Each complete program leaves exactly one Boolean. At runtime a loaded number may also be null. A comparison consuming a null is false, even when comparing two nulls. A question made entirely from constants can answer true on a missing row because it never reads the row.


If the checker names the wrong Boolean at a boundary, replay that row and write down the stack after each instruction. A type error that names an instruction index means the program's shape is wrong before any row is read, not that a row got the wrong answer. Read the instruction index in the error and compare the two type names it needs with the stack at that moment.
