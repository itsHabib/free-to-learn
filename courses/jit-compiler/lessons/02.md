# 02 · Emit a WebAssembly predicate

The interpreter rereads the same tuples for every row. You will translate the tuples once into a **WebAssembly** (Wasm) function, then pass rows directly to it. This is the compilation step in this JIT. Node decides how to execute WebAssembly on your machine. The comparison you generate takes one signed 32-bit integer and returns the integer 0 or 1.

Start with the passing interpreter from unit 01. Edit `compile` in `work/runtime.mjs`. You will write a short instruction-selection loop. `lib/wasm.mjs` already packs instructions into the binary file format, instantiates the module and hands back its exported function. You may consult the `compile` checkpoint in `reference/runtime.mjs` and record that help.

```js {"file":"examples/threshold-wasm.mjs","region":"threshold","title":"A function body for signed greater-than","change":"Trace each byte sequence before writing the general loop.","focus":[3,4,5]}
function over(threshold) {
  const bytes = [
    0x20, 0x00,                     // local.get 0
    0x41, ...signedI32(threshold),   // i32.const threshold
    0x4a,                           // i32.gt_s
  ];
  return instantiatePredicate(bytes);
}
```
<!-- /code-example -->

`local.get 0` reads argument zero and puts it on the Wasm operand stack. `i32.const` pushes the signed threshold. `i32.gt_s` takes the left and right integers off the stack, compares them as signed numbers and pushes a 0 or 1. The final item becomes the return value. The bytes spell the operations in the same order as our postfix tuples, so today's compiler can translate one instruction at a time. [WebAssembly Core 1.0](https://www.w3.org/TR/2019/REC-wasm-core-1-20191205/)

## Emit the program you actually received

Keep the supplied `validateProgram(program)` call at the top of `compile`. Under it, create an empty JavaScript array named `instructions`. Loop over the tuples as `for (const [op, literal] of program)`. Translate each tuple according to this table. When the loop ends, return `instantiatePredicate(instructions)`.

| Tuple | Bytes to append | What happens |
| --- | --- | --- |
| load | 0x20, 0x00 | Read argument zero |
| const, literal | 0x41, followed by all bytes from signedI32(literal) | Push the integer literal |
| gt | 0x4a | Compare two signed integers |
| eq | 0x46 | Compare two integers for equality |
| and | 0x71 | Apply bitwise AND to two 0/1 comparison results |

In JavaScript, `instructions.push(0x41, ...signedI32(literal))` appends each encoded byte. A fixed one-byte literal only works for part of the signed domain. Open `signedI32` in `lib/wasm.mjs`. Each byte contributes seven payload bits. Bit seven asks the decoder to continue, and the final payload's high bit supplies the sign. For example, 63 fits in one signed payload. The number 64 needs a second byte so its final sign is positive. See the binary integer and numeric-instruction encodings. [WebAssembly binary format](https://www.w3.org/TR/2019/REC-wasm-core-1-20191205/#binary-format%E2%91%A0)

Run this with your compiler. The constant appears first, so the generated predicate tests `-70 > value`.

```sh
node --input-type=module <<'JS'
import { compile, interpret } from './work/runtime.mjs';
const program = [['const', -70], ['load'], ['gt']];
const predicate = compile(program);
for (const value of [-71, -70, -69, 0]) {
  console.log(value, interpret(program, value), predicate(value));
}
JS
node lab.mjs check 02 --predict 'My riskiest signed boundary and why'
```

The two result columns should agree after translating false/true to 0/1. Temporarily change the greater-than opcode to `0x4b`, unsigned greater-than. Predict which line changes above, run again, then repair it. The integer bit patterns stay the same. Interpreting them as unsigned makes a negative integer rank above zero. That is how a generated filter can look correct across positive test inputs and still silently accept a wrong order.

Keep null values on the interpreter side of this API. A raw Wasm function taking i32 receives a numeric argument from JavaScript. Calling it with null would convert the missing value to an integer before your comparisons ran. The next unit will guard that boundary. [WebAssembly JavaScript interface](https://www.w3.org/TR/2019/REC-wasm-js-api-1-20191205/)

## New case · Compile a rule assembled at runtime

A store loads a list of minimum stock levels from a file. The order quantity must exceed **every** level. In `work/limits.mjs`, write a function that takes a nonempty array of thresholds and returns **one** postfix program. Compile it once. Build at least 40 requirements so the instruction body grows past the size of a single seven-bit length field. Include a negative threshold and place the largest one in the middle. This gives your `and` emission and the supplied module packer a different workload from a single literal.

Write assertions against the ordinary JavaScript question `limits.every(n => value > n)` for a value below the maximum, one exactly at it, and one above it. Run your own transfer check with `node work/limits.mjs`. If the long program fails to validate, trace the steps that join the first two comparisons.
