# 07 · Generate under limits

Connect prompt processing, cached decode and sampling into a local generator. Make its stopping reason explicit so a short result can be distinguished from an execution failure.

Goal: return generated tokens, text and an execution trace under deterministic limits. Depends on modules 01–06.

## Generation execution model

Validate a nonempty prompt and generation settings. Run prefill once. Its last logits predict the next token. Sample that token, append it to generated IDs and the complete token list, then either stop or feed the token into decodeStep to obtain logits for the following draw. Do not run prefill again on every iteration in the cached path.

```text
prompt -> prefill -> next logits -> sample token
                                  -> append and test stop
                                  -> decode appended token -> next logits
```

The sampled token that fills the context is returned. No later decode step is allowed. EOS is token zero: include it in generated IDs, omit it from decoded text and report stop="eos". If the requested number of new tokens is exhausted, report stop="limit". If context capacity ends first, report stop="context". A legitimate stop is not an execution error.

## Worked limit trace

A prompt with 31 tokens leaves one slot in context 32. Even if maxNewTokens is eight, at most one token may be appended. A prompt already at 32 returns no new tokens and stop="context". maxNewTokens=0 returns the unchanged prompt, no generated IDs and no draws. If the first sampled token is EOS, stop immediately after that one ID.

## Return contract

generate(model,prompt,{maxNewTokens=8,seed=1,temperature=1,topK=32}) returns {tokens,generated,text,stop,trace}. tokens includes the original prompt. generated contains only appended IDs. text decodes generated IDs only. Each trace record contains the cache position used to predict the sampled token and its token ID. Keep model, prompt, controls and seed in the caller's experiment notes.

The original fixture is untrained. Output is a local numerical demonstration, even if a string happens to resemble words. No pretrained model permission or language benchmark has been assumed. Your useful product here is a correct, inspectable execution runtime.

## Complete and build

Complete the loop with the stop tests blank, using already tested prefill, decodeStep and sample. Hand-trace the one-slot case before filling the conditions. Then implement generate and run module 07. The EOS control uses an original modified output head that makes greedy ranking choose EOS. Repeated-seed runs must return the same complete result and trace.

## Repair hints

Hint 1: count prompt tokens and newly appended tokens separately. Hint 2: inspect which logits produced the first token. Hint 3: test zero limit, full context and EOS without waiting for a long run. Do not label a stopped generation as a failed check merely because it produced fewer tokens than the requested maximum.

## Changed problem

Run the same prompt with greedy output and with a seeded positive temperature. Keep the numerical runtime fixed. Explain which differences come from sampling and which would signal an incorrect cache. Then prepare a second prompt for the capstone; its cache investigation will compare logits before sampling so random variation cannot conceal the cause.
