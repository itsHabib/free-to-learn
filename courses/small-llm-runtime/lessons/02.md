# 02 · Keep probabilities finite

Exponentiating a large score directly can overflow before you divide by the total. Implement probabilities whose result depends on score differences rather than a common score offset.

Goal: compute stable softmax and the pinned activation. Depends on module 01.

## Softmax mechanism

A logit is a score before conversion into probabilities. Softmax assigns exp(score)/sum(exp(scores)). Subtract the largest valid score from every score before exponentiating. The common exponential factor cancels, while the largest exponential becomes one. Divide each exponential by their sum. The result contains nonnegative probabilities summing to one within numeric precision.

This runtime uses -Infinity to mark a masked score: a score excluded from the distribution. Its exponential is zero.

Numeric validation must reject strings, null and missing values. The attention mask is the one explicit nonfinite exception. Every input must be a Number. Reject strings, null and missing elements; the only permitted nonfinite score is the -Infinity mask.

 Reject an empty row, NaN, positive Infinity or a row with every key masked. An all-masked row has no distribution to normalize. Converting it to a uniform row would invent attention to invalid positions.

## Worked example

Scores [1000,1001,-Infinity] become [-1,0,-Infinity]. Exponentiating gives [exp(-1),1,0], then normalization gives [1/(1+e),e/(1+e),0]. The softmax-extreme check compares this result with the shifted scores [-1000,-999,-Infinity]. The probabilities must agree.

## Activation

An activation transforms a hidden coordinate before another projection. The pinned MLP uses SiLU(x)=x/(1+exp(-x)). Large positive x approaches x; large negative x approaches zero. At x=0 the result is zero. With binary64, exp(1000) overflows to Infinity, but -1000 divided by that positive infinite denominator still yields finite negative zero. Avoid expressions that multiply Infinity by zero and produce NaN.

The silu-extreme check executes inputs [-1000,0,1000]. Numeric behavior at these extremes matters even though the tiny checkpoint rarely reaches them. A stable method must preserve the defined operation, not simply clip every value to a convenient constant.

## Complete and build

Warm up by hand: for scores [1000,1001,-Infinity], subtracting the maximum gives exponentials [e^-1, 1, 0]. Divide each by their sum and confirm that the row sums to one and the masked entry is zero. Then write the complete softmax implementation, including validation. Implement silu as a separate scalar operation. Run module 02.

The supplied numeric backend does not provide these target operations. It supplies finite-vector checking, vector addition, elementwise multiplication and row-vector matrix projection. You own the probability and activation logic.

## Repair hints

Hint 1: inspect shifted scores before exponentiating. Hint 2: compare the same scores with a common offset added. Hint 3: distinguish a legitimate zero probability from a nonfinite total. If every key is masked, return a clear error before division.

## Changed problem

An attention implementation masks a whole row because its prefix length was computed incorrectly. Decide whether the probability function should conceal that state or expose it, then construct a public case showing the chosen behavior. Later modules return to this distinction when an invalid cache looks like a numeric failure. Keep an extreme-score case in your regression checks while adding normalization and attention.
