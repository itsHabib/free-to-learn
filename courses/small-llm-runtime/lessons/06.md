# 06 · Make sampling reproducible

Identical logits can produce different sampled tokens. Make that choice reproducible so a cache repair can be tested without also changing the random experiment.

Goal: implement the pinned seeded generator, temperature and top-k controls. Depends on module 02; this module can be checked without a completed attention runtime.

## Ranking and probabilities

Temperature zero selects a highest-scoring token without drawing randomness. Resolve equal scores by ascending token ID. With positive temperature, divide retained scores by temperature, compute stable softmax, draw a number u in [0,1), and select the first cumulative probability greater than u.

topK retains the K highest scores before softmax. Sort by descending score and then ascending token ID; K must be an integer between one and vocabulary size. This runtime requires all 32 sampling logits to be finite. Attention masks belong in attention, not in the final output distribution. Reject negative or nonfinite temperature and invalid random draws.

A positive temperature can be very small. Subtract the largest retained logit before dividing by temperature; otherwise finite positive logits can overflow during division before softmax gets a chance to shift them. This preserves the same distribution and leaves the largest scaled score at zero.

## Worked sampling example

Two retained tokens have equal logits, so each has probability one half. If their sorted IDs are 2 and 4, draw 0.25 selects 2 and draw 0.75 selects 4. The half-open interval rule handles exact boundaries: draw 0.5 belongs to the second interval. A draw of one is invalid rather than a request for the final token.

## Pinned random sequence

The seed is an unsigned 32-bit integer. Maintain state as an unsigned 32-bit integer and update it with state=(1664525*state+1013904223) modulo 2^32. Use Math.imul for the low 32 bits of multiplication. Return state/4294967296. The API rng(seed) returns a function that performs one update per call. This recurrence is a reproducibility contract for the teaching runtime, not a source of security randomness.

A seed alone does not define an experiment. Changing how many draws occur changes later tokens. Greedy sampling must consume no draw. Keep ranking and tie behavior stable as well.

## Complete and build

Complete a cumulative interval selection with the probability vector already supplied. Next compute those probabilities from ranked logits. Implement rng and sample(logits,{temperature,topK},random). The random function argument makes fixed-draw tests possible; the complete generator will supply rng(seed). Run module 06.

The checks include tied maxima, cumulative-interval boundaries, repeated seed sequences and invalid controls. They establish agreement with the pinned sampling rule on those cases; they do not assess generated text quality.

## Repair hints

Hint 1: print the ranked token IDs before exponentiating. Hint 2: use a supplied draw instead of a seed while testing one distribution. Hint 3: compare the first random state and count draws. If two identical seeded runs disagree, inspect accidental calls to Math.random or shared generator state.

## Changed problem

Create a logit vector with a tie exactly at the top-k cutoff. Decide which token remains, then use draws on both sides of a cumulative boundary. Keep this test when integrating generation. A different model checkpoint or prompt can change logits; a different seed changes only the sampling experiment after those logits are computed.
