# 05 · Reuse keys and values

Recomputing an entire prefix is a useful reference route. A cache avoids recomputing old keys and values, but it adds state whose identity and contents must remain correct.

Goal: make one-token cached decode agree with full-prefix computation. Depends on module 04. Numeric parity comes before a performance claim.

## Cache execution model

prefill(model,tokens) computes the prompt once. Return its last logit vector and the full cache. The cache position counts processed tokens. For a prefix of length p, the appended token uses zero-based rotary position p. Each block appends one rotated key row and one unrotated value row. The new query attends to all cached rows including the new row.

```text
prefill [a,b,c] -> rows at positions 0,1,2; cache.position=3
decode token d -> compute new query/key at position 3
               -> append one key/value per block
               -> attend to positions 0..3
               -> return last logits; new cache.position=4
```

The new token's input to the next block is its current residual output, not its original embedding. Earlier rows in that next block are already present in its separate cache.

## Worked parity trace

Start with prompt [4]. Append [5,3,6,7] one token at a time. After each append, compare decodeStep's logits with the last logits from forward on the entire prefix. The cache-incremental-parity check also compares each position with the independent scalar oracle. Agreement at only the first position cannot catch an offset that begins to fail later.

## Validation and isolation

Before any mutation, validate cache format, fingerprint, position, block count, row counts, row widths and finite values. Each key/value list must have exactly position rows. A cache at the context limit cannot accept another decode step. Reject a cache from another checkpoint even if dimensions agree.

decodeStep returns a new cache and leaves its input unchanged. This lets two requests continue from the same prefix without corrupting one another. It is acceptable to share genuinely immutable old rows; copying rows is simpler for this small model. New outer arrays that still mutate shared inner arrays do not satisfy isolation.

## Complete and build

Begin with the one-token computation from module 04 and leave only the append step blank. Complete that step, then replace recomputation of old rows with reads from cache. Implement prefill and decodeStep(model,token,cache). Return {logits,cache}. Run module 05.

The validation check intentionally breaks a later block's key length. If your code appends to an earlier block before discovering it, it has already damaged the input. Validate the whole cache first, then compute the new state.

## Repair hints and changed problem

Hint 1: compare cache.position with every row count. Hint 2: compare the new key before attention. Hint 3: compare one block's output with a full-prefix trace before inspecting later blocks. Avoid changing sampling while diagnosing numeric parity; no token draw is needed here.

Fork one valid prefix into two different next tokens. Check both results against full recomputation and verify that the shared original prefix remains byte-for-byte unchanged. The capstone changes the failure again: a cache will have valid dimensions but incorrect content.
