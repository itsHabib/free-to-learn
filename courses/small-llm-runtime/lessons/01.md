# 01 · Load exactly one model

A model file can have familiar dimensions and still contain the wrong bytes or tensor names. Build a loader that accepts exactly the original teaching model this course defines.

Goal: validate a checkpoint and convert text into its token IDs. Prerequisites are the entry JavaScript and matrix skills. The supplied numeric.mjs backend is complete and independent of the tensor course.

## Pinned model

PocketDecoder-v1 is an original, deliberately tiny decoder-only teaching architecture. It has model width 8, two heads of width 4, two blocks, hidden width 16, vocabulary size 32 and context length 32. It uses binary64 numbers on the CPU. This format makes no compatibility claim with another model family.

The included 21,661-byte checkpoint was generated from an original deterministic script. Its parameters are untrained. It supports arithmetic and cache investigations, not claims about language quality. No pretrained checkpoint was downloaded or packaged. An external asset would need its own redistribution review and is outside this offline route.

## Loader mechanism and worked example

The file format is ivy-pocket-json-v1. A tensor has shape and data fields; matrices store row-major data and map a row vector through a [inputWidth,outputWidth] weight. spec.mjs defines the exact configuration and vocabulary. fixtures/manifest.json supplies the expected SHA-256 of the checkpoint bytes.

First compare the byte digest. Then parse JSON and validate the format, configuration, vocabulary, tensor inventory, shapes and finite numeric values. The embedding shape is [32,8]; a query matrix in either block is [8,8]. A correctly hashed file with a missing query matrix must still fail. A shape [4,16] also contains 64 values but has different semantics and must fail.

## Tokens and execution model

A token ID is an integer index into the vocabulary. IDs 0 through 3 represent EOS, unknown, newline and space. IDs 4 through 29 represent lowercase a through z, followed by period and comma. Iterate Unicode code points; an unsupported code point maps to unknown ID 1. Do not drop it. Decoding omits EOS, renders unknown as the replacement character, and rejects out-of-range or noninteger IDs.

Worked tokenization: "a b" becomes [4,3,5]. A prompt is a nonempty token array. There is no automatic beginning-of-sequence token. Later, each ID selects one embedding row, which becomes the first hidden vector for that position.

## Complete and build

Before coding, write down the order of your loader checks: digest, format, config fields, vocabulary, tensor names and shapes, then finite numeric values. Every check runs before any weight is used. In runtime.mjs implement loadModel, encode and decode. sha256 is supplied because file hashing is outside the course's target skills. Return the validated model with fingerprint equal to the expected digest. Keep its parameters immutable during inference.

Run module 01. The malformed controls carry newly computed matching hashes, so a loader that checks only the hash and then accepts the bytes fails them. Those controls test rejection only: a stub that always throws also passes them while failing the valid-checkpoint cases. A few passing rejection cases therefore do not show a usable loader or a module pass. The tokenizer check includes an unsupported Unicode code point and a newline.
