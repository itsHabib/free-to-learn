# 03 · Build a decoder block

A decoder block changes each position's vector while preserving its model width. Build its normalization and gated feed-forward calculation before adding communication between positions.

Goal: apply learned RMS normalization and the pinned gated MLP. Depends on module 02. Matrix projection is supplied by numeric.mjs.

## Normalization mechanism

RMSNorm divides a vector by the square root of its mean squared coordinate plus epsilon, then multiplies each coordinate by its learned gain. The model's epsilon is 1e-5. A gain vector has the same width as the input. Validate all values and require positive finite epsilon.

Worked normalization: x=[2,-2], gains=[1,2], epsilon=1. The mean square is 4, so the divisor is sqrt(5). The output is [2/sqrt(5),-4/sqrt(5)]. A zero input remains zero because epsilon keeps the denominator positive.

Squaring or dividing can overflow. Rearrange the same formula to keep intermediate magnitudes bounded.

Finite coordinates can overflow when squared. To preserve the same formula at large magnitudes, divide by the largest absolute coordinate before squaring, compute the scaled root mean square, then restore its scale. Combine that result with sqrt(epsilon) using a stable hypotenuse calculation. Handle the all-zero vector separately. The large-finite check uses opposite values of magnitude 1e300; their normalized magnitudes should remain one before gains are applied.

## Gated MLP mechanism

An MLP here is a position-wise calculation that projects the model vector into a wider hidden vector and back. SwiGLU uses two input projections. Apply SiLU to x@w1, multiply that vector elementwise by x@w3, then project through w2. With model width d and hidden width f, w1 and w3 have shape [d,f], while w2 has shape [f,d]. There are no bias vectors in this pinned architecture.

```text
x [d] -> w1 [d,f] -> SiLU --+
                           multiply -> w2 [f,d] -> output [d]
x [d] -> w3 [d,f] ----------+
```

Worked gating before the final projection: an activated branch [2,3] and gate [4,0] produce [8,0]. Adding those branches would implement a different block. The executable MLP check uses a nonidentity output matrix to expose both a missing gate and a transposed-weight convention.

## Complete and build

Warm up by hand: RMSNorm of [2,-2] with epsilon 1 is [2,-2]/sqrt(5) before the gain; with gains [1,2] it becomes [2/sqrt(5),-4/sqrt(5)]. For a gated MLP, the activated branch and the gate branch are multiplied element by element before the output projection. Implement rmsNorm and mlp in runtime.mjs, using the supplied matrix projection if you wish. Run module 03.

In the complete decoder, these operations sit inside residual paths. A residual adds the block output back to its input, so the vector width must agree. Module 04 specifies the complete order; do not guess the order from tensor names.

## Repair hints

Hint 1: label every vector and matrix width. Hint 2: inspect the two hidden projections before multiplying. Hint 3: use unequal values and a nonidentity w2 to distinguish a transposed matrix from an omitted gate. If an all-zero case passes, still test nonzero gains; zero cannot expose a missing gain multiplication.
