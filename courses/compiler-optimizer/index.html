What must an optimization preserve?

A faster kernel is unusable if it changes the records it returns or modifies. Implement compare(sourceResult, targetResult) so the workbench can distinguish equal completed behavior from a discrepancy or an unfinished run.

Prerequisites: functions, arrays and basic compiler terminology. Read the observation shapes in API.md. The interpreter, input reader and execution limits are supplied.

Decide what can be observed

Kernel IR returns an i8, i32 or bool value. It can also store into input arrays, append typed events, or terminate with a defined trap. All of those observations matter. Instruction identifiers, elapsed work and the arrangement of blocks do not.

Consider two runs that return i8 6. The first emits i8 2 and then i8 5; the second emits i8 5 and then i8 2. The return values agree, but the ordered event sequences differ. Comparing the event set would lose information.

For a normal return, compare the return type and value, all heap object identities/types/cells, and events in order. For a trap, compare its code and the heap/events that existed before it. Object-map key order is irrelevant; cell and event order are meaningful.

Separate program behavior from an incomplete experiment

A bounds trap is part of this IR's meaning. Running out of fuel is an incomplete observation of the program. Two loops reaching the same fuel limit have not demonstrated equivalent final behavior.

A useful comparator first asks whether both results completed as return or trap. It then compares the relevant fields. It must return false for unknown or invalid results; the surrounding validator will classify those separately rather than call them counterexamples.

Do not compare every property indiscriminately: optimization is expected to change counters. Do not discard fields just because the current example does not use them.

SSA, control flow and dominance

A substituted value may be numerically right yet unavailable on a path. Implement dominators(program) so your optimizer can establish where a definition is usable.

Prerequisite: U01, directed graphs and sets. The supplied cfg utility returns predecessor and successor lists; you own the dominance analysis.

Compute availability across every path

Block A dominates block B when every entry-to-B path passes through A. Each block dominates itself. The entry dominates every reachable block.

For a diamond E → L/R → J, the dominator sets are E:{E}, L:{E,L}, R:{E,R}, J:{E,J}. Neither arm dominates J because the other arm supplies a path avoiding it.

A practical fixed-point procedure initializes entry to {entry} and every other reachable block to the set of all blocks. Repeatedly replace a non-entry block's set with itself plus the intersection of its predecessors' sets. Stop only when every set is unchanged. Initializing all non-entry blocks to just themselves would discard necessary facts rather than compute this solution.

Apply the procedure by hand to a graph with a backedge before coding. Return sorted arrays keyed by block ID; block storage order must not influence the answer.

Commit item 02a using question and answer.

A phi uses values on edges

A phi selects the value associated with the predecessor that actually transferred control. Its incoming values must be available at their own predecessor terminators, not necessarily on every path into the successor.

In a loop, a body-defined next counter can feed a header phi on the backedge even though the body does not dominate the first entry into the header. The initial incoming value handles that first entry.

All selected phi inputs are read from the predecessor environment before any new phi result is written. This matters when two loop variables exchange values. The supplied interpreter implements this rule; your analysis must not reject valid backedge uses.

A useful scalar optimizer

The calibration kernel computes the same multiplication twice and carries unnecessary constant work. Implement scalar(program, contract) to reduce its executed work while emitting a checked edit chain.

Prerequisites: U01–U02. Use the supplied Editor; return editor.finish(). You choose opportunities and ordering. The editor checks the rule premises and records exact before/after identities.

Fold only under the declared arithmetic

An i8 multiplication of constants 90 and 3 produces 14: the mathematical product 270 wraps modulo 256. An i32 multiplication of the same constants produces 270. Use the supplied word primitives rather than JavaScript Number multiplication for arbitrary i32 operands.

A constant fold requires known constant operands and the exact operation/type. The result becomes a typed constant with the original result ID. Folding can make its original constants unused, but that is a separate edit.

For example, after establishing the correct result for a particular definition, an edit has this shape:

editor.edit({kind: 'fold', id: chosenID, value: canonicalValue});

This is an edit request, not permission to invent a value. Wrong values are rejected.

Reuse and remove with distinct premises

Reuse requires the same total, pure expression and an available earlier result. Addition and multiplication permit operand-order normalization; signed comparisons do not. A definition in one arm of a diamond is not available in the other arm merely because the expressions match.

Dead-result removal requires no remaining use, including return, branch, phi and effect operands, and a total pure instruction. An unused load can still trap. Store and emit are observable even without result IDs.

Commit items 03a and 03b before looking at their feedback. Implement folding, safe reuse and dead-result cleanup. Revisit opportunities after an edit: folding can expose dead constants, and reuse can make a definition unnecessary. Avoid unbounded loops when no edit succeeds.

Conditional constants and dataflow

A constant condition can make an edge unreachable, which can make a phi constant. Implement constants(program, contract) as a convergent sequence of justified value and control-flow simplifications.

Prerequisite: Project A. Your earlier scalar pass can be factored into a helper, but its edits must stay in one continuous evidence chain.

Values and control flow inform each other

Suppose entry branches on the known false value. Only its false successor executes. A downstream phi no longer needs the removed edge's value. If its remaining input is a constant, the phi can be replaced with that constant, exposing more scalar folds.

Do not confuse a currently unseen edge with an impossible edge. In a general constant-propagation analysis, value facts distinguish not-yet-known, one known constant, and varying/unknown values. Joining different possible constants loses the constant claim. Executable edges determine which incoming values contribute.

Our checked-edit core is deliberately conservative: first fold provable literal computations, simplify a branch whose condition is now a literal, repair the CFG, and fold phis whose remaining inputs agree. Repeat to a fixed point. This teaches the coupling without making an unverified sparse solver part of the trusted base.

Make iteration explicit

Keep a worklist or repeat a full sweep. Either is acceptable at this scale. The loop must stop when there are no new justified edits. Recompute or invalidate dependent facts after changing the program; the old digest identifies the old graph.

A header phi with initial value zero and a backedge increment is not the constant zero merely because you visited entry first. Test at least two loop iterations. A single first-trip test cannot expose a frozen loop-carried fact.

The editor's branch operation removes newly unreachable blocks and obsolete phi inputs as one verified transaction. Do not manually omit that cleanup or claim stale analysis applies to the new program.

Aliases and effects

Two parameter names can reference the same cell. Implement aliases and memory so a memory optimization depends on static evidence rather than an input that happened to work.

Prerequisites: U02–U04. The heap model, pointer arithmetic and checked memory edits are supplied.

Distinguish names, objects and cells

A pointer is an object ID plus an element offset. Different objects cannot overlap in this IR. Two offsets within one typed object name the same cell only when the offsets are equal. No byte reinterpretation or object lifetime change exists.

For static analysis, a pointer parameter is a symbolic base. A ptradd by a constant changes its symbolic offset. Two expressions with the same base and equal offsets must alias; the same base with different offsets cannot alias. Different unknown parameter bases may alias unless the frozen contract explicitly separates their objects.

A concrete run with p on object A and q on object B does not establish a static NoAlias claim for every invocation.

Commit items 05a and 05b.

Reuse a value across only safe effects

Consider a load through p, a store through q, then another load through p. If q may alias p, the store invalidates the saved value. If the contract proves distinct objects, the saved value can still serve the later load.

Scan backward from a load or maintain available memory values while scanning forward. A same-location earlier load or store supplies a value. A possibly aliasing intervening store blocks reuse. An emit does not change memory in this language, but it must remain in the event sequence.

The earlier access also matters for traps. If it fails, execution never reaches the later load. If it succeeds, fixed object size and the identical address make the later access in bounds. This is more precise than declaring every load pure.

Move loop work without changing behavior

A computation repeated inside a loop may be moved once to its preheader. Implement loops(program, contract) so the move remains valid for zero-trip loops and aliased memory.

Prerequisites: dominance, conditional constants and alias/effect reasoning.

Find a supported natural loop

A backedge from latch L to header H has H dominating L. Starting from L, walk predecessors backward until H to collect the loop's blocks. The required profile has one latch and one outside predecessor serving as preheader. Exits are dedicated to the loop. Unsupported shapes should remain unchanged.

A value is invariant when its operands are available outside the loop or are values you have already moved in a valid order. Moving an instruction changes availability, so revisit dependent instructions.

For total scalar arithmetic, executing it earlier cannot add a trap or event. It can change work on a zero-trip input. That is a profitability issue, addressed separately in U07.

Commit item 06a.

A load needs more than an invariant pointer

A pointer can stay fixed while a store changes its contents. A load can also be skipped by the original program and trap if executed speculatively.

Our required load-motion profile is narrow: the frozen contract establishes a fixed, in-bounds address, and no loop store may alias it. The contract is checked on every input. A single observed nonempty array is not a proof for future arrays.

The editor records the move and checks the loop, availability, bounds and write premises. Your analysis chooses which operation to propose. It does not gain permission to invent a stronger contract.

Evidence, pass order and cost

A report that says “all tests passed” is incomplete without its subjects, domain and limits. Implement decide(report) to select a supported, beneficial translation and retain the previous program otherwise.

Prerequisites: Projects A and B. Hashing, execution, case accounting and report serialization are supplied.

Read the evidence before the number

EXHAUSTIVE_WITHIN_DOMAIN means every member of a declared nonempty finite domain completed equally. It does not mean every input of every size was checked. SAMPLED_NO_DIFFERENCE is weaker. UNKNOWN means required execution or coverage did not finish. INVALID means the subjects, inputs or evidence are malformed/inconsistent. COUNTEREXAMPLE records a completed mismatch.

A demonstrated counterexample is useful even if some other cases were not completed. A cutoff on the last case prevents an exhaustive success. Neither conclusion depends on whether the average runtime looked good.

Every receipt binds the original/candidate programs, input contract and listed inputs. The edit-chain check detects changes that were never described by a rewrite event. Current identities, successful rule checks and completed domain coverage are separate requirements.

Decide whether the change earns its place

This workbench counts executed IR operations with unit weights. Phi assignments count as value work; their simultaneous group is one interpreter fuel step. This model is reproducible, but it is not machine cycles.

Compare identical input lists. A safe hoist may add a load on a zero-trip input while saving many loads on longer runs. Report those per-input changes and the total under the chosen workload. Do not call an aggregate benefit a worst-case speedup.

Commit item 07b. Require current identities, a checked rule chain, exhaustive required-domain success, complete comparable costs and a strict aggregate improvement. A correct no-op ties the baseline rather than improving it.

Reduce a miscompilation

A small, stable wrong-result example is easier to explain and repair than a large failing program. Implement reduce(program, input, transform) so simplification preserves the same legal miscompilation.

Prerequisite: U07. The guided fault reuses memory incorrectly; the final investigation uses a different optimization.

Define the interestingness predicate first

For each proposed source and input, regenerate the target using the supplied transform. Verify both programs, execute them from separate fresh heaps and require normal returns that differ in value or observable heap. A parser crash, a new bounds trap or an exhausted budget is not the required wrong-result witness.

Suppose irrelevant constant arithmetic is removed and the same source/target return discrepancy persists. That is useful reduction. Removing a definition used by the return and making the program invalid is not.

Commit item 08a.

Keep three internal decisions: interesting, not interesting, and unresolved. You may skip an unresolved candidate and preserve the best known witness, but you cannot use it as evidence that no smaller witness exists.

The supplied inspectWitness helper reports those three states and preserves both executions. Start with a deliberately tiny fuel budget and observe UNRESOLVED, then restore enough fuel. This is an execution-budget experiment, not a new counterexample. An exception inside the faulty transform is also unresolved; it cannot certify a clean neighborhood.

Reduce structure and input without losing identity

Try a finite family of legal changes, such as deleting unused total computations or simplifying an input value. A supplied Editor can enforce structural safety for eligible source changes; the interestingness check still has to rerun the faulty transform.

Accept only a strictly smaller candidate under a declared measure. Keep the signature, semantics and faulty pipeline fixed. Never manually edit only the target to preserve an apparent discrepancy. Recheck the final witness from fresh state.

Use the supplied lexicographic measure: block count, definitions/instructions, operand occurrences, heap objects, heap cells, then numeric-value complexity. Numeric complexity counts magnitude bits (plus a sign bit for a negative offset), not printed characters. Simplifying a witness word from 7 to 0 decreases it; shortening the program name or renaming an SSA value does not. Property order and whitespace also do not count. A smaller value cannot compensate for adding a block. Values can tie under this declared order; do not claim every possible simplification is ranked. Keep a trace of candidates, decisions and the best accepted witness. You design the candidate family and search order; the helper supplies execution and accounting.

A greedy reducer can produce a useful best-found result. Claim 1-minimality only after checking every permitted single-step reduction of the final candidate with no interesting or unresolved neighbor. That is still not a global minimum.

Pass that final candidate list to assessNeighborhood. Its NO_SMALLER_IN_LIST report establishes only the list it actually inspected. Explain why your list covers your declared family, or label the result best-found. A family containing only one convenient edit is weak evidence even when completely checked.

Transfer: an unfamiliar optimization

A foreign pass rewrites a packet-window kernel. Investigate it without a worked diagnosis, then replace its faulty behavior while retaining useful optimization.

Prerequisites: U01–U08. Create your own work/project.mjs; no project implementation is supplied. API.md specifies its interface.

Establish an original witness

Your project receives the original program and an inspectable transform. Read the IR and the transform, state a hypothesis and search for an input satisfying the declared signature. Require valid source and target programs, normal returns and a value or heap discrepancy.

The precise issue is not given here. Use the integer, control-flow and effect rules already established. A familiar-looking algebraic transformation is not evidence that its premises hold.

Retain the original program and input before reducing. The automated check will regenerate the target itself; an invented target or a manually edited output is not accepted.
