## The shader language

A **shader** is a short program the GPU runs once for each pixel a triangle covers, to decide its colour. One run of it, for one pixel, is a **lane**. A lane has 16 **registers**, r0 to r15, each holding one 32-bit floating-point number, a **float32**. Here is the course's Lambert shader, which lights a surface by how squarely it faces a light:

<!-- code-example {"file":"examples/shaders.txt","region":"lambert","language":"text","title":"scenes/shaders/lambert.asm","change":"Study: supplied."} -->
```text {"file":"examples/shaders.txt","region":"lambert","title":"scenes/shaders/lambert.asm","change":"Study: supplied."}
; Lambert diffuse: the vertex colour times how squarely the surface
; faces a fixed light, plus a little ambient so shadowed faces are
; not black. Normals are unit length (each face has one normal).
.in r g b nx ny nz                ; r0 r1 r2 = colour, r3 r4 r5 = normal
.const light 0.30305 0.80812 0.50508  ; unit vector towards the light
mul r6, r3, light.x
mad r6, r4, light.y, r6
mad r6, r5, light.z, r6           ; r6 = n . light
max r6, r6, 0                     ; a face turned away gets no light
mad r6, r6, 0.8, 0.2              ; 20% ambient, 80% diffuse
mul r0, r0, r6
mul r1, r1, r6
mul r2, r2, r6
out r0, r1, r2
```
<!-- /code-example -->

Each instruction takes one line, with its destination register first where it has one, and `;` starts a comment. `.in` copies interpolated attributes, the values lesson 3's `interpolate` produced at the pixel, into r0, r1 and on in the order named, from `r g b u v nx ny nz` (colour, texture coordinates, and the normal, the unit-length direction the surface faces). `.const` names up to four numbers, read as `light.x` to `light.w`, or as `light.r` to `light.a` when they are a colour. `mad d, a, b, c` is d = a × b + c.

These are all the ops. A source operand `a`, `b` or `c` is a register, a constant or a number:

| Op | What it does |
| --- | --- |
| `mov d, a` | d = a |
| `add d, a, b`, `sub`, `mul` | d = a + b, a − b, a × b |
| `mad d, a, b, c` | d = a × b + c |
| `min d, a, b`, `max` | the smaller, the larger |
| `rcp d, a` | d = 1 / a, the reciprocal |
| `rsq d, a` | d = 1 / √a, the reciprocal square root |
| `floor d, a`, `frac` | the whole number at or below a; a − floor(a) |
| `slt d, a, b` | d = 1 if a < b, else 0 ("set if less than") |
| `sge d, a, b` | d = 1 if a ≥ b, else 0 ("set if greater or equal") |
| `tex d, u, v, NAME` | reads texture NAME at (u, v) into four registers from d |
| `out r, g, b` | sets the pixel's colour |
| `if a` … `else` … `endif` | runs the `if` side when a is not 0, otherwise the `else` side |
| `loop` … `break a` … `endloop` | repeats the body; `break` leaves the loop when a is not 0 |

## Assembling a program

`assemble(text)` turns the text into `{ code, inputs, consts }`. Each entry of `code` is `{ op, args, line }`, and an operand is `{ r: 3 }` for a register, `{ k: 0.8 }` for a number or constant, or `{ tex: 'floor' }` for a texture. The supplied `OPS` table says what each op takes:

<!-- code-example {"file":"examples/shader.txt","region":"OPS","language":"js","title":"OPS, in project/gpu/shader.mjs","change":"Study: supplied."} -->
```js {"file":"examples/shader.txt","region":"OPS","title":"OPS, in project/gpu/shader.mjs","change":"Study: supplied."}
// Operand kinds per op. 'dst' is a register written, 'src' a value
// read (register, constant or number), 'dst4' a register that
// starts four (tex writes RGBA), 'tex' a texture name.
export const OPS = {
  mov: ['dst', 'src'],
  add: ['dst', 'src', 'src'],
  sub: ['dst', 'src', 'src'],
  mul: ['dst', 'src', 'src'],
  mad: ['dst', 'src', 'src', 'src'],
  min: ['dst', 'src', 'src'],
  max: ['dst', 'src', 'src'],
  rcp: ['dst', 'src'],
  rsq: ['dst', 'src'],
  floor: ['dst', 'src'],
  frac: ['dst', 'src'],
  slt: ['dst', 'src', 'src'],
  sge: ['dst', 'src', 'src'],
  tex: ['dst4', 'src', 'src', 'tex'],
  out: ['src', 'src', 'src'],
  if: ['src'],
  else: [],
  endif: [],
  loop: [],
  break: ['src'],
  endloop: [],
};
```

The supplied `parseLine` turns one line into an instruction, or `null` for a blank line, a comment or a directive. Two supplied names in it: `lineError(line, why)` makes an error whose message starts `line N:`, and `CONTROL` lists the six jump ops, `if` to `endloop`, whose instructions get a `match` object for their targets:

<!-- code-example {"file":"examples/shader.txt","region":"parseLine","language":"js","title":"parseLine, in project/gpu/shader.mjs","change":"Study: supplied, with OPS, parseOperand and directive above it."} -->
```js {"file":"examples/shader.txt","region":"parseLine","title":"parseLine, in project/gpu/shader.mjs","change":"Study: supplied, with OPS, parseOperand and directive above it."}
// One line of text to an instruction { op, args, line }, or null for
// a blank line, a comment or a directive (which fills prog).
export function parseLine(raw, prog, line) {
  const words = raw.split(';')[0].split(/[\s,]+/).filter(Boolean);
  if (words.length === 0) return null;
  const [op, ...rest] = words;
  if (op.startsWith('.')) {
    directive(op, rest, prog, line);
    return null;
  }
  const kinds = OPS[op];
  if (!kinds) throw lineError(line, `unknown op '${op}'`);
  if (rest.length !== kinds.length) {
    throw lineError(line, `${op} takes ${kinds.length} operands, ` +
      `not ${rest.length}`);
  }
  const args = rest.map((t, j) =>
    parseOperand(t, kinds[j], prog.consts, line));
  const ins = { op, args, line };
  if (CONTROL.includes(op)) ins.match = {}; // filled in by assemble
  return ins;
}
```
<!-- /code-example -->

Your `assemble` calls `parseLine` for every line, counting lines from 1, and pushes each instruction:

<!-- code-example {"file":"examples/shader.txt","region":"assemble","language":"js","title":"assemble, in project/gpu/shader.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/shader.txt","region":"assemble","title":"assemble, in project/gpu/shader.mjs","change":"Write route: replace the throw line with this body."}
export function assemble(text) {
  const prog = { code: [], inputs: [], consts: {} };
  const open = []; // if and loop entries still waiting for their end
  text.split(/\r?\n/).forEach((raw, i) => {
    const line = i + 1;
    const ins = parseLine(raw, prog, line);
    if (!ins) return;
    const { op } = ins;
    const at = prog.code.length;
    const top = open.at(-1);
    if (op === 'if' || op === 'loop') open.push({ ins, at, later: [] });
    if (op === 'else') {
      // one else per if; where it jumps is not known until endif
      if (top?.ins.op !== 'if' || top.ins.match.else !== undefined) {
        throw lineError(line, 'else without an open if, or a 2nd else');
      }
      top.ins.match.else = at;
      top.later.push(ins);
    }
    if (op === 'break') {
      const loop = open.findLast((o) => o.ins.op === 'loop');
      if (!loop) throw lineError(line, 'break outside a loop');
      loop.later.push(ins);
    }
    if (op === 'endif' || op === 'endloop') {
      const want = op === 'endif' ? 'if' : 'loop';
      if (top?.ins.op !== want) {
        const inner = !top ? '' :
          ` (the ${top.ins.op} on line ${top.ins.line} is still open)`;
        throw lineError(line, `${op} without an open ${want}${inner}`);
      }
      open.pop();
      // the end is known now: fill in the targets that pointed ahead
      for (const x of [top.ins, ...top.later]) x.match.end = at;
      if (op === 'endloop') ins.match.start = top.at;
    }
    prog.code.push(ins);
  });
  const left = open.at(-1)?.ins;
  if (left) throw lineError(left.line, `${left.op} is never closed`);
  return prog;
}
```

## Jumping ahead

The language has `if a`, `else`, `endif`, `loop`, `break a` and `endloop`. When an `if` is false the lane must jump to its `else` or `endif`, which come later in the text, so `assemble` can't know the target when it reads the `if`. It keeps each open `if` and `loop` on a list with the instructions that will need its end. An `else` fills in its `if`'s `match.else` as soon as it is read, and `match.end`, and for an `endloop` `match.start`, are filled in when the closing line arrives. Targets are instruction numbers in `code`, counted from 0. This shader branches on a checker of squares:

<!-- code-example {"file":"examples/shaders.txt","region":"checker-branch","language":"text","title":"scenes/shaders/checker-branch.asm","change":"Study: supplied."} -->
```text {"file":"examples/shaders.txt","region":"checker-branch","title":"scenes/shaders/checker-branch.asm","change":"Study: supplied."}
; A checker of 8 x 8 squares in (u, v), shaded with a branch: dark
; squares take the if side, light squares the else side. Pixels on
; either side of a square's edge disagree, so a warp that straddles
; an edge runs both sides.
.in u v r g b                     ; r0 = u, r1 = v, r2 r3 r4 = colour
mul r5, r0, 8
floor r5, r5                      ; column
mul r6, r1, 8
floor r6, r6                      ; row
add r5, r5, r6
mul r5, r5, 0.5
frac r5, r5                       ; 0.5 on odd squares, 0 on even
if r5
  mul r2, r2, 0.3                 ; dark square: a dim, cool copy
  mul r3, r3, 0.35
  mul r4, r4, 0.45
else
  mad r2, r2, 0.6, 0.4            ; light square: towards white
  mad r3, r3, 0.6, 0.4
  mad r4, r4, 0.6, 0.38
endif
out r2, r3, r4
```

## Errors that name the line

A shader with a mistake must stop with a message that starts `line N:`, counting from 1, so the writer can find it. The mistakes are an unknown op, the wrong number of operands, a register past r15, an unknown constant, an `endif` with no open `if`, or an `if` that is never closed. `parseLine` throws the first four, and your `assemble` throws the rest.

## One lane's arithmetic

`step(lane, ins, env)` carries out one instruction that isn't a jump, on one lane's registers. The supplied `read(lane, o)` gives an operand's value: the register's for `{ r }`, the number for `{ k }`. `mov`, `min`, `max`, `floor`, `slt` and `sge` return one of their float32 inputs or a whole number, so they need no rounding:

<!-- code-example {"file":"examples/shader.txt","region":"step","language":"js","title":"step, in project/gpu/shader.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/shader.txt","region":"step","title":"step, in project/gpu/shader.mjs","change":"Write route: replace the throw line with this body."}
export function step(lane, ins, env) {
  const f = Math.fround;
  const r = lane.r;
  const [x, y, z] = ins.args.slice(1).map((o) => read(lane, o));
  if (ins.op === 'out') {
    lane.out = ins.args.map((o) => read(lane, o));
    return;
  }
  const d = ins.args[0].r;
  switch (ins.op) {
    case 'mov': r[d] = x; break;
    case 'add': r[d] = f(x + y); break;
    case 'sub': r[d] = f(x - y); break;
    case 'mul': r[d] = f(x * y); break;
    // round the product first, as a separate multiply and add would
    case 'mad': r[d] = f(f(x * y) + z); break;
    case 'min': r[d] = Math.min(x, y); break;
    case 'max': r[d] = Math.max(x, y); break;
    case 'rcp': r[d] = f(1 / x); break;
    case 'rsq': r[d] = f(1 / Math.sqrt(x)); break;
    case 'floor': r[d] = Math.floor(x); break;
    // x - floor(x): frac(-0.25) is 0.75, the distance up from floor
    case 'frac': r[d] = f(x - Math.floor(x)); break;
    case 'slt': r[d] = x < y ? 1 : 0; break;
    case 'sge': r[d] = x >= y ? 1 : 0; break;
    case 'tex': r.set(env.tex(ins.args[3].tex, x, y), d); break;
    default: throw new Error(`step: ${ins.op} is not an arithmetic op`);
  }
}
```

## Float32 arithmetic

A GPU's shader core stores every result as a float32, which keeps about 7 significant digits. JavaScript numbers are 64-bit, so `step` rounds every result with `Math.fround`, and `mad` rounds twice, the product and then the sum, as a separate multiply and add would. A GPU may instead fuse them into one operation with one rounding; the course has not measured which GPUs do. For `lambert.asm` the two differ only in the last bit, far below one 8-bit colour level, and the measured comparisons matched on every unit. That is not true of every shader: subtracting nearly equal numbers or comparing with a threshold, as the toon shader will, can turn that last bit into a different colour. Take a = 1 + 2⁻¹² in a register. With two roundings, `mad r1, r0, r0, -1` gives exactly 2⁻¹¹ = 0.00048828125, because the product's last bits are rounded away before the subtraction.

## Negative and zero inputs

The course fixes what `frac`, `rcp` and `rsq` return for inputs that are negative or 0. `frac(x)` is `x - floor(x)`, the distance up from the whole number below, so `frac(-0.25)` is 0.75, not −0.25. `rcp 0` is `Infinity` and `rsq 0` is `Infinity`, as on a GPU, and in this course `rsq` of a negative number is NaN, as `Math.sqrt` gives. `frac(-1e-8)` is exactly 1 in float32, because 1 − 10⁻⁸ rounds up.

## Sixteen registers

A lane's registers are a `Float32Array(16)`, so storing a value rounds it to float32 too. The assembler rejects `r16`, and `tex` rejects a destination above r12, because it writes four registers: red, green, blue and alpha, the texel's opacity, which no shader in this course uses.

## Textures and the colour

`tex d, u, v, NAME` reads texture NAME at (u, v) through `env.tex` and writes red, green, blue and alpha into d to d + 3. `out r, g, b` sets the lane's colour, `lane.out`, the value the pipeline stores for the pixel.

In this course `env.tex` reads the nearest texel. A GPU's texture unit can also filter, and with bilinear filtering, the `'linear'` mode of lesson 4's `sample`, the shader receives a blend of the four texels around the point.

## Running a shader

The supplied `runLane` runs one pixel's program. It starts with the supplied `loadLane`, which makes a fresh lane and copies the `.in` attributes into r0, r1 and on, and it stops a loop that never breaks after `MAX_ISSUES`, 1,000,000 issues. It counts one **issue** for every instruction it carries out, and it does the jumps itself. A false `if` jumps past its `else`, an `else` reached from the `if` side jumps to its `endif`, a taken `break` leaves its loop and `endloop` goes back to the top:

<!-- code-example {"file":"examples/shader.txt","region":"runLane","language":"js","title":"runLane, in project/gpu/shader.mjs","change":"Study: supplied."} -->
```js {"file":"examples/shader.txt","region":"runLane","title":"runLane, in project/gpu/shader.mjs","change":"Study: supplied."}
// One fragment, one instruction at a time. One issue per instruction
// executed. A false if jumps past its else (or to its endif); an else
// reached by running the if side jumps to its endif; a taken break
// jumps past its endloop; endloop jumps back to just after its loop.
export function runLane(program, attrs, env) {
  const lane = loadLane(program, attrs);
  const code = program.code;
  let pc = 0;
  let issues = 0;
  while (pc < code.length) {
    const ins = code[pc];
    const m = ins.match;
    const yes = () => read(lane, ins.args[0]) !== 0;
    issues += 1;
    if (issues > MAX_ISSUES) {
      throw new Error(`runLane: over ${MAX_ISSUES} issues: a loop ` +
        'never breaks');
    }
    if (ins.op === 'if') {
      pc = yes() ? pc + 1 : m.else === undefined ? m.end : m.else + 1;
    } else if (ins.op === 'else') pc = m.end;
    else if (ins.op === 'break') pc = yes() ? m.end + 1 : pc + 1;
    else if (ins.op === 'endloop') pc = m.start + 1;
    else if (ins.op === 'endif' || ins.op === 'loop') pc += 1;
    else {
      step(lane, ins, env);
      pc += 1;
    }
  }
  return { out: lane.out, issues };
}
```

## A toon shader

A **toon** shader lights a surface in flat bands instead of a smooth fade. Write one in the course's language as `project/transfer/toon.asm`. It takes `.in r g b nx ny nz`, computes d = n · light, the sum nx × 0.30305 + ny × 0.80812 + nz × 0.50508, with a `mul` and two `mad`s in the same order as the first three instructions of `lambert.asm`, and outputs the colour times 0.35 where d is below 0.3, times 0.7 from 0.3 up to 0.75, and the colour itself from 0.75 up.

Then write its twin, `project/transfer/toon.glsl`, in the form of `scenes/shaders/lambert.glsl`, a function `vec3 shade(vec3 color, vec2 uv, vec3 n)` with the same light, band edges and levels. GLSL is the shading language WebGL runs, and its `highp float` is a float32. The comparison page adds the `#version` line and the `highp` precision itself, so the file holds only the light and `shade`:

```text {"file":"examples/shaders.txt","region":"lambert-glsl","title":"scenes/shaders/lambert.glsl","change":"Study: supplied. toon.glsl has the same form."}
// GLSL twin of lambert.asm, in the comparison page's function form:
// the page adds the #version line, highp precision and the varyings,
// and calls shade() with the interpolated colour, uv and normal.
// highp float is float32, so each line below rounds as the assembly
// does. One place may differ: a GPU may fuse a * b + c into one
// rounding where the assembly's mad rounds twice (a last-bit change,
// far below one 8-bit level).
const vec3 light = vec3(0.30305, 0.80812, 0.50508);

vec3 shade(vec3 color, vec2 uv, vec3 n) {
  float d = n.x * light.x;
  d = n.y * light.y + d;
  d = n.z * light.z + d;            // n . light, in the same order
  d = max(d, 0.0);
  d = d * 0.8 + 0.2;                // 20% ambient, 80% diffuse
  return color * d;
}
```

Check both:

```sh
node lab.mjs check 5
```

The check runs your assembly with your `assemble` and the supplied `runLane` on ten normals and colours and allows 1 level. Node can't run GLSL, so the check only reads the GLSL text: it looks for the band edges compared with d and for a return that uses the levels, but it can't tell whether the bands come out right. To see the bands themselves, draw the courtyard with your toon shader on both sides, your assembly on your GPU and its GLSL twin in WebGL:

```sh
node lab.mjs compare 5 project --shader project/transfer/toon.asm
```

`project` is your project folder, as in the other commands, and `--shader FILE` draws the courtyard with FILE on your GPU in place of the scene's own shader. The lab picks up `toon.glsl` beside `toon.asm` for the WebGL side. Read the verdict at the end. "Your pictures match WebGL's" means the twin draws the same bands. If it says the pictures differ, `toon.asm` and `toon.glsl` compute different colours for some pixels, and the verdict counts them.
