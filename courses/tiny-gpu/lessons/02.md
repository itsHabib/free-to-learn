## Matrices and homogeneous points

A corner of the courtyard is a point (x, y, z) in metres, with y up. Give it a fourth number, w = 1, and it becomes a **homogeneous coordinate** (x, y, z, 1). A **4 × 4 matrix** moves such a point. Each of its four rows, multiplied number by number with (x, y, z, 1) and summed, gives one number of the result. The 16 numbers are stored **column-major**, as WebGL stores them, so row r, column c sits at `m[c * 4 + r]`. Because w = 1, the fourth column, `m[12]` to `m[15]`, is added to every point. A matrix that is all zeros except 1s down its diagonal and `m[12] = 2` moves every point 2 m along x.

<!-- code-example {"file":"examples/vertex.txt","region":"transform","language":"js","title":"transform, in project/gpu/vertex.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/vertex.txt","region":"transform","title":"transform, in project/gpu/vertex.mjs","change":"Write route: replace the throw line with this body."}
// m is column-major: row r, column c sits at m[c * 4 + r].
export function transform(m, p) {
  const [x, y, z] = p;
  const out = [0, 0, 0, 0];
  for (let r = 0; r < 4; r++) {
    out[r] = m[r] * x + m[4 + r] * y + m[8 + r] * z + m[12 + r];
  }
  return out;
}
```
<!-- /code-example -->

The pipeline makes one matrix per camera from two supplied ones. `lookAt` moves the world so the eye sits at the origin, looking down −z. `perspective` then turns that into **clip space**, four numbers (x, y, z, w) per corner. Notice its last row, row 3 counting from 0, in `m[3]`, `m[7]`, `m[11]` and `m[15]`. It's (0, 0, −1, 0), so the clip w of a point is −z, its distance in front of the eye. A point is in view when x, y and z each lie between −w and w.

<!-- code-example {"file":"examples/matrix.txt","region":"perspective","language":"js","title":"perspective, in project/gpu/matrix.mjs","change":"Study: supplied."} -->
```js {"file":"examples/matrix.txt","region":"perspective","title":"perspective, in project/gpu/matrix.mjs","change":"Study: supplied."}
// fovY in degrees. A point at distance near lands on z = -w, a point
// at distance far on z = w; w is the distance in front of the eye.
export function perspective(fovY, aspect, near, far) {
  const f = 1 / Math.tan((fovY * Math.PI) / 360);
  const m = new Float64Array(16);
  m[0] = f / aspect;
  m[5] = f;
  m[10] = (far + near) / (near - far);
  m[11] = -1;
  m[14] = (2 * far * near) / (near - far);
  return m;
}
```

## The divide and the snap

Dividing x, y and z by w is the **perspective divide**, and it makes far things small. The same 1 m to the right, twice as far away, lands half as far from the centre. After it, a visible point has x and y between −1 and 1, which `toWindow` maps to 0 to W and 0 to H pixels and snaps to the 1/16 pixel grid from lesson 1 with `Math.round`. It also keeps two numbers for lesson 3, the depth `z / w` mapped to 0 to 1, and `1 / w`.

<!-- code-example {"file":"examples/vertex.txt","region":"toWindow","language":"js","title":"toWindow, in project/gpu/vertex.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/vertex.txt","region":"toWindow","title":"toWindow, in project/gpu/vertex.mjs","change":"Write route: replace the throw line with this body."}
// Divide by w, map -1..1 to the picture, snap to 1/16 of a pixel.
export function toWindow(c, W, H) {
  const [x, y, z, w] = c;
  return {
    x: Math.round(((x / w + 1) / 2) * W * SUB),
    y: Math.round(((y / w + 1) / 2) * H * SUB),
    z: (z / w + 1) / 2,
    invW: 1 / w,
  };
}
```
<!-- /code-example -->

`toWindow` rounds, as `snap2` does in lesson 1, rather than cutting off the fraction. `Math.trunc` moves every corner up to 1/16 pixel towards zero, and the GPU doesn't, so coverage along those edges would differ.

Its w is −2, so x / w flips sign and the point lands left of centre, inside the picture, although it's behind you and to your right. A triangle with one corner behind the eye stretches across the screen the wrong way round. So the GPU cuts each triangle before the divide, at the **near plane**, the plane 0.1 m in front of the eye where clip z equals −w. A corner is in front of it when `z + w >= 0`.

`clipNear` walks the edges v0 → v1 → v2 → v0. It keeps each corner in front, and where an edge goes from one side to the other it adds the crossing point. With d_s and d_e the values of `z + w` at the edge's start and end, that point lies a fraction t = d_s / (d_s − d_e) of the way along the edge. Every attribute, the numbers a corner carries in `a` beside its clip position `c`, is blended by the same t. The kept polygon has 3 or 4 corners, or none, and comes back as triangles that fan out from its first corner. The check compares the triangles corner by corner in that order:

<!-- code-example {"file":"examples/vertex.txt","region":"clipNear","language":"js","title":"clipNear, and the supplied between, in project/gpu/vertex.mjs","change":"Write route: replace the throw line with this body. between is supplied."} -->
```js {"file":"examples/vertex.txt","region":"clipNear","title":"clipNear, and the supplied between, in project/gpu/vertex.mjs","change":"Write route: replace the throw line with this body. between is supplied."}
// Keep the part of a triangle in front of the near plane z = -w.
export function clipNear(tri) {
  const dist = (v) => v.c[2] + v.c[3];
  const poly = [];
  for (let k = 0; k < 3; k++) {
    const s = tri[k];
    const e = tri[(k + 1) % 3];
    const ds = dist(s);
    const de = dist(e);
    if (ds >= 0) poly.push(s);
    // A vertex exactly on the plane is already in the list.
    const crosses = (ds > 0 && de < 0) || (ds < 0 && de > 0);
    if (crosses) poly.push(between(s, e, ds / (ds - de)));
  }
  // The polygon (3 or 4 corners) as a fan around its first corner.
  const out = [];
  for (let k = 1; k + 1 < poly.length; k++) {
    out.push([poly[0], poly[k], poly[k + 1]]);
  }
  return out;
}

function between(s, e, t) {
  const mix = (from, to) => from.map((x, i) => x + t * (to[i] - x));
  return { c: mix(s.c, e.c), a: mix(s.a, e.a) };
}
```

Only the near plane is cut. Pieces that run off the sides of the picture are left whole, and `rasterize` clamps its bounding box to the framebuffer. Cutting at the sides would put new corners at off-grid positions and change exact coverage. The cost is large coordinates. Over the course's camera stops, the named positions the lab draws the courtyard from, a clipped corner's window coordinate reaches 196,017 subpixels, which is 12,251 pixels, far outside the 160 by 120 picture, and an edge value can reach (2 × 196,017)², about 1.5 × 10¹¹. That is still far below 2⁵³, about 9.0 × 10¹⁵, the largest integer a JavaScript number holds exactly, so the edge functions stay exact.

## The courtyard in perspective

The supplied `windowTris` in `pipeline.mjs` runs your three functions on every corner of every triangle. Notice that a 2D scene skips them and only snaps, which is why lesson 1's scenes still draw:

<!-- code-example {"file":"examples/pipeline.txt","region":"windowTris","language":"js","title":"windowTris, in project/gpu/pipeline.mjs","change":"Study: supplied."} -->
```js {"file":"examples/pipeline.txt","region":"windowTris","title":"windowTris, in project/gpu/pipeline.mjs","change":"Study: supplied."}
// One scene triangle -> 0, 1 or 2 window triangles of
// { x, y, z, invW, a } (x, y in subpixels).
export function windowTris(tri, ctx) {
  const { target, vp } = ctx;
  if (!vp) {
    const pts = snap2(tri.v.map((v) => v.p));
    return [tri.v.map((v, k) => ({
      x: pts[k][0], y: pts[k][1],
      z: v.p[2] ?? 0.5, invW: 1 / (v.p[3] ?? 1), a: attrsOf(v),
    }))];
  }
  const clip = tri.v.map((v) => ({
    c: transform(vp, v.p), a: attrsOf(v),
  }));
  return clipNear(clip).map((piece) => piece.map((cv) => ({
    ...toWindow(cv.c, target.w, target.h), a: cv.a,
  })));
}
```
