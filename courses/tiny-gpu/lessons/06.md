## Eight lanes, one issue

A **warp** is eight lanes that share one **program counter**, the number of the instruction to run next (`pc` in lesson 5's `runLane`). Its lanes are the pixels of a 4 by 2 block whose bottom-left pixel (x0, y0) has x0 a multiple of 4 and y0 a multiple of 2. Pixel (x, y) is lane (y − y0) × 4 + (x − x0), so lanes 0 to 3 are the bottom row. The GPU fetches and decodes each instruction once, one **issue**, and every lane carries it out on its own registers. Real GPUs use wider warps, for example 32 lanes on AMD's RDNA GPUs and 64 on its older GCN GPUs. This course uses 8 so that a whole warp fits in a diagram. One pixel at a time, the floor of lesson 5 took 249,600 issues, 13 for each of its 19,200 pixels.

## The active mask

A warp at a triangle's edge has lanes whose pixels the triangle doesn't cover. Those lanes must not run, or they would write colour outside the triangle. The **active mask** is an 8-bit integer, bit k for lane k. Lane k runs an instruction only when bit k is 1. The supplied `runBlock` in `pipeline.mjs` builds each warp's lanes and its starting mask from the fragments that passed the depth test, then calls your `runWarp`:

<!-- code-example {"file":"examples/warp.txt","region":"runWarp","language":"js","title":"runWarp, in project/gpu/warp.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/warp.txt","region":"runWarp","title":"runWarp, in project/gpu/warp.mjs","change":"Write route: replace the throw line with this body."}
export function runWarp(program, lanes, mask, env, opts = {}) {
  const code = program.code;
  let st = { pc: 0, mask, stack: [] };
  let issues = 0;
  while (st.pc < code.length) {
    const ins = code[st.pc];
    // one issue per instruction visited, however many lanes run it
    issues += 1;
    const handler = HANDLERS[ins.op];
    if (handler) {
      st = handler(st, ins, lanes, opts);
      continue;
    }
    for (let k = 0; k < LANES; k++) {
      // inactive lanes keep their registers and their colour
      if (st.mask & (1 << k)) step(lanes[k], ins, env);
    }
    st.pc += 1;
  }
  return { issues };
}
```
<!-- /code-example -->

Three names in `runWarp` come from elsewhere. `LANES` is 8, supplied in `warp.mjs`. `step` is lesson 5's function that carries out one instruction on one lane. `HANDLERS`, also supplied, maps each instruction that moves the program counter to the function that handles it. Those instructions are `if`, `else`, `endif`, `loop`, `break` and `endloop`:

<!-- code-example {"file":"examples/warp.txt","region":"HANDLERS","language":"js","title":"HANDLERS, in project/gpu/warp.mjs","change":"Study: supplied."} -->
```js {"file":"examples/warp.txt","region":"HANDLERS","title":"HANDLERS, in project/gpu/warp.mjs","change":"Study: supplied."}
export const HANDLERS = {
  if: onIf, else: onElse, endif: onEndif,
  loop: onLoop, break: onBreak, endloop: onEndloop,
};
```
<!-- /code-example -->

Each handler takes the warp's state `{ pc, mask, stack }` and returns the next one.

## If, else and endif

An `if` narrows the mask to the active lanes where its operand isn't 0. It pushes a stack entry holding two masks: `saved`, the mask it found, and `taken`, the lanes that took the `if` side. The `else` side runs on the other lanes of the saved mask, `saved & ~taken` in JavaScript's bitwise and-not. The `endif` pops the entry and brings `saved` back as the mask. The supplied `lanesWhere` finds the lanes that take the `if`:

<!-- code-example {"file":"examples/warp.txt","region":"lanesWhere","language":"js","title":"lanesWhere, in project/gpu/warp.mjs","change":"Study: supplied."} -->
```js {"file":"examples/warp.txt","region":"lanesWhere","title":"lanesWhere, in project/gpu/warp.mjs","change":"Study: supplied."}
// The active lanes (bits of mask) where operand a is not zero.
export function lanesWhere(lanes, mask, a) {
  let bits = 0;
  for (let k = 0; k < LANES; k++) {
    if (mask & (1 << k) && read(lanes[k], a) !== 0) bits |= 1 << k;
  }
  return bits;
}
```
<!-- /code-example -->

`onIf` jumps straight past an `if` side that no lane takes, unless `opts.skip` is `false`. "Skipping an empty side" below says why. Here is `onIf`:

<!-- code-example {"file":"examples/warp.txt","region":"onIf","language":"js","title":"onIf, in project/gpu/warp.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/warp.txt","region":"onIf","title":"onIf, in project/gpu/warp.mjs","change":"Write route: replace the throw line with this body."}
export function onIf(st, ins, lanes, opts) {
  const taken = lanesWhere(lanes, st.mask, ins.args[0]);
  st.stack.push({ kind: 'if', saved: st.mask, taken });
  if (taken === 0 && opts.skip !== false) {
    // no lane takes the if side: go to the else (it runs) or endif
    const pc = ins.match.else ?? ins.match.end;
    return { pc, mask: taken, stack: st.stack };
  }
  return { pc: st.pc + 1, mask: taken, stack: st.stack };
}
```
<!-- /code-example -->

`onElse` and `onEndif` have no listing. Write their bodies from these rules, in the starter's signatures `onElse(st, ins, lanes, opts)` and `onEndif(st)`:

- `onElse` reads the top entry of `st.stack` and leaves the stack unchanged. The new mask is the lanes of `saved` that aren't in `taken`, `saved & ~taken`. When that mask is 0 and `opts.skip` isn't `false`, it jumps to the `endif` at `ins.match.end`, as `onIf` jumps over an empty `if` side. Otherwise the program counter moves on to `st.pc + 1`.
- `onEndif` pops the top entry, and the program counter moves on to `st.pc + 1` with that entry's `saved` as the mask.
- Both return `{ pc, mask, stack }`, with the same `stack` array they were given.

A worked trace. A warp at a triangle's edge reaches an `if` with mask 11111100, written lane 7 first, so lanes 0 and 1 are off. The operand isn't 0 on lanes 2, 3 and 6, so `onIf` pushes `saved` = 11111100 and `taken` = 01001100, and the `if` side runs on 01001100. At the `else`, `onElse` returns the mask 11111100 & ~01001100 = 10110000, lanes 4, 5 and 7, and the next instruction. At the `endif`, `onEndif` pops the entry, and the mask is 11111100 again. Had every active lane taken the `if`, `taken` would equal `saved`, the `else` mask would be 0, and `onElse` would jump straight to the `endif`.

## Divergence

When the lanes of a warp disagree about an `if`, the warp **diverges**. It runs the `if` side on some lanes and then the `else` side on the others, and every lane waits through both. A warp whose lanes all agree runs one side, because `onIf` and `onElse` jump over a side that no lane takes.

## The mask stack

An `if` inside another `if` pushes a second entry, whose `saved` is the outer `if`'s narrowed mask. Its `else` flips within that mask only, so a lane switched off by the outer `if` stays off. Each `endif` pops its own entry. A single saved mask in place of a stack would let the inner `if` overwrite the outer one's.

The inner entry's `saved` is 01111110, lanes 1 to 6, and its `taken` is 00001100, because lanes 0 and 7 were already off. Its `else` runs on 01110010. Lanes 0 and 7 wait for the outer `else`.

## Loops and break

The supplied `onLoop`, `onBreak` and `onEndloop` keep a warp in a loop while any lane is still in it. A lane whose `break` fires drops out of the mask, and out of every `if` entry opened inside the loop, so no `endif` brings it back early. When no lane is left, the warp goes to the `endloop`, which pops the loop's entry and restores the lanes that entered:

<!-- code-example {"file":"examples/warp.txt","region":"onBreak","language":"js","title":"onBreak, in project/gpu/warp.mjs","change":"Study: supplied, with onLoop and onEndloop beside it."} -->
```js {"file":"examples/warp.txt","region":"onBreak","title":"onBreak, in project/gpu/warp.mjs","change":"Study: supplied, with onLoop and onEndloop beside it."}
// Lanes where the operand is not zero leave the loop: they drop out of
// the mask and out of every if entry opened inside the loop, so no
// endif or else brings them back. When no lane is left in the loop
// (and skipping), drop those if entries and go to the endloop.
export function onBreak(st, ins, lanes, opts) {
  const leaving = lanesWhere(lanes, st.mask, ins.args[0]);
  const mask = st.mask & ~leaving;
  let i = st.stack.length - 1;
  let alive = mask;
  for (; st.stack[i].kind !== 'loop'; i--) {
    st.stack[i].saved &= ~leaving;
    alive |= st.stack[i].saved;
  }
  if (alive === 0 && opts.skip !== false) {
    st.stack.length = i + 1;
    return { pc: ins.match.end, mask: 0, stack: st.stack };
  }
  return { pc: st.pc + 1, mask, stack: st.stack };
}
```

## Skipping an empty side

When no lane takes the `if` side, `onIf` jumps straight to the `else`, or to the `endif`, and the warp doesn't step through instructions that would run on no lane. `onElse` does the same when no lane is left for the `else` side. With `opts.skip` set to `false`, a warp walks every line of both sides. The jumps use the targets your `assemble` filled in, `match.else` and `match.end`, instruction numbers counted from 0.
