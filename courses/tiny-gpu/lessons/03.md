## Smooth colour

`rasterize` hands `emit` three edge values for each covered pixel. Divided by their sum, they become **barycentric weights**, b0, b1 and b2, which add up to 1. Each says how close the pixel is to one corner, and b0 is 1 at v0 and 0 all along the edge opposite it. At pixel (4, 3) of lesson 1's triangle the edge values were 9,088, 5,248 and 4,608, out of 18,944, so the weights are 0.480, 0.277 and 0.243. A colour at the pixel is then b0 × c0 + b1 × c1 + b2 × c2, and the framebuffer stores each channel as a level from 0 to 255:

  return Math.round(Math.min(1, Math.max(0, c)) * 255);

## Perspective-correct interpolation

In 3D, equal steps on the screen aren't equal steps on the surface. The far half of a floor tile takes fewer pixels than the near half, so blending by screen weights alone spreads the far corner's colour too far towards the near corner. Take lesson 1's `one-triangle` scene again, coloured red, green and blue at its corners, with clip w of 1, 6 and 2.5. The green corner is six times as far from the eye as the red one.

Every pixel is off by more than a level, and the worst by 107 of 255, because a colour varies evenly across the surface in 3D, while the divide by w squeezes the far part on screen. What does vary evenly on screen is the colour divided by w, and 1 / w itself. So **perspective-correct** interpolation blends a / w, for each attribute a such as a colour channel, and 1 / w with the screen weights, then divides the first blend by the second:

    a = (b0 a0/w0 + b1 a1/w1 + b2 a2/w2) / (b0/w0 + b1/w1 + b2/w2)

With w of 1 at red v0 and 6 at green v1, the pixel halfway between them on screen gets weights q = 0.5 × 1 and 0.5 × 1/6, so green's share is 0.083 / 0.583, a seventh. Halfway on screen is a seventh of the way along the real edge. Depth `z / w` already varies evenly on screen, so it takes the screen weights with no correction:

<!-- code-example {"file":"examples/interp.txt","region":"interpolate","language":"js","title":"interpolate, in project/gpu/interp.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/interp.txt","region":"interpolate","title":"interpolate, in project/gpu/interp.mjs","change":"Write route: replace the throw line with this body."}
// w = the three edge values rasterize handed to emit.
export function interpolate(v, w, n) {
  const sum = w[0] + w[1] + w[2];
  const b = [w[0] / sum, w[1] / sum, w[2] / sum];
  // z / w is linear on screen, so depth uses the screen weights.
  const z = b[0] * v[0].z + b[1] * v[1].z + b[2] * v[2].z;
  // Attributes are linear in the world: weight each vertex by its
  // 1/w, then divide by the interpolated 1/w.
  const q = [b[0] * v[0].invW, b[1] * v[1].invW, b[2] * v[2].invW];
  const qSum = q[0] + q[1] + q[2];
  const attrs = new Array(n);
  for (let k = 0; k < n; k++) {
    const s = q[0] * v[0].a[k] + q[1] * v[1].a[k] + q[2] * v[2].a[k];
    attrs[k] = s / qSum;
  }
  return { z, attrs };
}
```

## The depth buffer

Drawing in the scene's order lets a far triangle drawn late cover a near one. The **depth buffer** keeps, for every pixel, the depth of the nearest fragment drawn there so far. It's a `Float32Array` cleared to 1, the depth of the far plane. A fragment passes the test only when its depth is strictly less than the stored one, the rule WebGL calls `LESS`, and then its depth is stored. The buffer holds 32-bit floats, so the test rounds z to float32 with `Math.fround` before comparing:

<!-- code-example {"file":"examples/interp.txt","region":"depthTest","language":"js","title":"depthTest, in project/gpu/interp.mjs","change":"Write route: replace the throw line with this body."} -->
```js {"file":"examples/interp.txt","region":"depthTest","title":"depthTest, in project/gpu/interp.mjs","change":"Write route: replace the throw line with this body."}
// LESS: a fragment wins only if strictly nearer than what is stored.
export function depthTest(depth, i, z) {
  const zf = Math.fround(z); // the buffer holds float32, compare those
  if (!(zf < depth[i])) return false;
  depth[i] = zf;
  return true;
}
```
<!-- /code-example -->

`drawTriangle` now interpolates every fragment, tests its depth, and shades only the ones that pass. Notice that `rasterize`'s three edge values go straight to your `interpolate`:

<!-- code-example {"file":"examples/pipeline.txt","region":"drawTriangle","language":"js","title":"drawTriangle, in project/gpu/pipeline.mjs","change":"Study: supplied."} -->
```js {"file":"examples/pipeline.txt","region":"drawTriangle","title":"drawTriangle, in project/gpu/pipeline.mjs","change":"Study: supplied."}
// Rasterize one window triangle inside rect, depth-test (stage 3+),
// shade the survivors and write them.
export function drawTriangle(tri, win, rect, ctx) {
  const { target, stage } = ctx;
  const frags = [];
  const covered = ctx.memory ? [] : null; // for unit 7's counts
  const pts = win.map((v) => [v.x, v.y]);
  rasterize(pts, rect, (x, y, w0, w1, w2) => {
    const i = y * target.w + x;
    target.counts.fragments++;
    covered?.push({ x, y });
    if (stage < 3) return void frags.push({ x, y, i, attrs: null });
    const f = interpolate(win, [w0, w1, w2], ATTRS.length);
    if (depthTest(target.depth, i, f.z)) {
      frags.push({ x, y, i, attrs: f.attrs });
    }
  });
  const colours = ctx.shade(tri, frags);
  target.counts.shaded += frags.length;
  frags.forEach((f, k) =>
    writePixel(target, f.i, colours[k], tri.id, f.attrs));
  if (covered) countFramebuffer(ctx, covered, frags);
}
```

## Equal depth keeps the first draw

The same triangle drawn twice lands at exactly the same depth at every pixel. Under `LESS` the second draw loses every tie, so a red triangle followed by a green copy stays red on all 1,492 pixels. Both GPUs this course measured do exactly that. The float32 rounding also decides ties: a depth of 0.1 is stored as 0.10000000149011612, so a test that compares the unrounded 0.1 with the stored value finds the second draw nearer. In the check's red and green copies, that hands 771 of the 1,492 pixels to the second draw.

## Fog from depth

Fog fades a surface towards the sky colour the further the surface lies from the eye, for example by a fraction `(d - 20) / (80 - 20)`, held between 0 and 1, where d is the distance in front of the eye in metres. That distance is the clip w from lesson 2, measured along the view. The straight-line distance from the eye would be another choice, but it doesn't vary evenly across a triangle in 3D, so this task uses w.
