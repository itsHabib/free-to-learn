## Nearest sampling

A **texture** is a small picture laid on a triangle, `{ w, h, data }`, its **texels** stored as 4 bytes each (red, green, blue, alpha) with row 0 at the bottom. The interpolated texture coordinates (u, v) run from 0 to 1 across it. Texel (x, y) covers u from x / w to (x + 1) / w, so its centre is at u = (x + 0.5) / w. **Nearest** sampling picks the texel that holds the point, `(floor(u × w), floor(v × h))`, and returns its colour as floats from 0 to 1.

## Repeat wrapping

Texture coordinates can run past 1 or below 0, and the course's textures **repeat**. Texel −1 is the last texel and texel w is the first. The supplied `texel` wraps x and y that way, with `((x % w) + w) % w`, because JavaScript's `%` keeps the sign of x.

## Bilinear filtering

**Bilinear** filtering blends the four texels around the point instead of taking one. It steps back half a texel, x = u × w − 0.5, so that x lands on whole numbers at texel centres. Then texels x0 = floor(x) and x0 + 1 are weighted 1 − fx and fx, where fx = x − x0, and the same in y:

<!-- code-example {"file":"examples/texture.txt","region":"sample","language":"js","title":"sample, in project/gpu/texture.mjs","change":"Write route: replace the throw line with this body. texel is supplied."} -->
```js {"file":"examples/texture.txt","region":"sample","title":"sample, in project/gpu/texture.mjs","change":"Write route: replace the throw line with this body. texel is supplied."}
export function sample(tex, u, v, mode) {
  if (mode === 'nearest') {
    return texel(tex, Math.floor(u * tex.w), Math.floor(v * tex.h));
  }
  if (mode !== 'linear') throw new Error(`sample: unknown ${mode}`);
  // Texel centres sit at +0.5, so step back half a texel first.
  const x = u * tex.w - 0.5;
  const y = v * tex.h - 0.5;
  const x0 = Math.floor(x);
  const y0 = Math.floor(y);
  const fx = x - x0;
  const fy = y - y0;
  const c00 = texel(tex, x0, y0);
  const c10 = texel(tex, x0 + 1, y0);
  const c01 = texel(tex, x0, y0 + 1);
  const c11 = texel(tex, x0 + 1, y0 + 1);
  return c00.map((_, k) =>
    (1 - fx) * (1 - fy) * c00[k] + fx * (1 - fy) * c10[k]
    + (1 - fx) * fy * c01[k] + fx * fy * c11[k]);
}

// Repeat wrapping: texel -1 is the last one, texel w the first.
function texel(tex, x, y) {
  const tx = ((x % tex.w) + tex.w) % tex.w;
  const ty = ((y % tex.h) + tex.h) % tex.h;
  const i = (ty * tex.w + tx) * 4;
  const d = tex.data;
  return [d[i] / 255, d[i + 1] / 255, d[i + 2] / 255, d[i + 3] / 255];
}
```

## Diffing two pictures

`diffImages(mine, theirs, ties)` compares two pictures the way the course judges them. Coverage comes first. A pixel whose triangle ids differ counts in `coverage`, and its colour isn't compared. If `ties` marks its centre as exactly on an edge, it counts in `onTies` too. Only where both pictures drew the same triangle does it compare red, green and blue, keeping the largest difference in `maxLevel` and counting the pixels more than 1 level apart in `overOne`:

<!-- code-example {"file":"examples/diff.txt","region":"diffImages","language":"js","title":"diffImages, in project/gpu/diff.mjs","change":"Write route: replace the throw line with this body. channelGap is supplied."} -->
```js {"file":"examples/diff.txt","region":"diffImages","title":"diffImages, in project/gpu/diff.mjs","change":"Write route: replace the throw line with this body. channelGap is supplied."}
// Coverage first: a pixel owned by different triangles is a coverage
// mismatch and its colour is not compared. Colour is compared (r, g,
// b) only where both pictures drew the same triangle.
export function diffImages(mine, theirs, ties) {
  if (mine.w !== theirs.w || mine.h !== theirs.h) {
    throw new Error('diffImages: the pictures differ in size');
  }
  let coverage = 0;
  let onTies = 0;
  let maxLevel = 0;
  let overOne = 0;
  for (let i = 0; i < mine.ids.length; i++) {
    if (mine.ids[i] !== theirs.ids[i]) {
      coverage++;
      if (ties && ties[i]) onTies++;
      continue;
    }
    if (mine.ids[i] < 0) continue;
    const level = channelGap(mine.rgba, theirs.rgba, i);
    maxLevel = Math.max(maxLevel, level);
    if (level > 1) overOne++;
  }
  return { coverage, onTies, maxLevel, overOne };
}

function channelGap(a, b, i) {
  let gap = 0;
  for (let k = 0; k < 3; k++) {
    gap = Math.max(gap, Math.abs(a[i * 4 + k] - b[i * 4 + k]));
  }
  return gap;
}
```

## Where the rules fix the answer

A pixel whose centre is inside one triangle and outside the others, with no edge near it, has one owner. A centre exactly on an edge that two triangles share, in a 2D scene with its corners on the grid, is drawn by exactly one of them, never both and never neither. The nearer depth wins, and an equal depth keeps the first draw. A texture coordinate well inside a texel picks that texel. The verdict requires all of these exactly, and the 2D tie scenes and the coplanar pair, a triangle and a copy at the same depths, match at every pixel on both backends the course measured.

Which of the two triangles draws a tie is the GPU's own convention. WebGL requires exactly one and leaves the choice to the implementation. Both backends measured here use lesson 1's top-left rule, and the comparison page names the rule it finds on yours. On a GPU with another rule, the verdict says that every difference sits on an edge and calls it a different convention, not a fault in your rasterizer.

WebGL leaves three more choices to the GPU. For each one the verdict allows a difference only within a band no wider than that choice, and lists those pixels separately:

- **Its arithmetic near edges.** The GPU works out corners and edges in float32. Near a long edge whose ends lie far off screen, float32 rounding can put a centre that lies a small fraction of a grid step from the edge on its other side. A pixel may differ when its centre lies within the band an edge can sweep if each end moves by at most one grid step, `|edge(a, b, centre)| ≤ |b.x − a.x| + |b.y − a.y|` in grid units. A tie in a 2D scene gets no band, although its edge value of 0 meets that inequality, and must match. SwiftShader gives 7 pixels of the overdraw scene, a 2D scene from lesson 8 whose corners are exactly on the grid, to the neighbouring triangle, all within 0.14 of a step from such an edge.
- **Texel edges.** The GPU computes u in float32, about ten operations, each within 2⁻²⁴ of the values involved. A nearest sample may differ when u × w is within 2⁻¹⁶ times the triangle's largest texel coordinate of a texel edge; 2⁻¹⁶ is 256 times float32's step of 2⁻²⁴. The Apple GPU's 74-level pixel sits 9.5e-7 from one.
- **Bilinear weights**, within 1 level, as above.

The bands let one mistake through. Snapping by cutting off the fraction instead of rounding moves every corner by less than one step, so it passes the comparison, and only the Node check `2.to-window` catches it. On the same recorded run the comparison caught 29 of the course's 30 deliberately broken versions of the reference GPU that change a picture, on both backends.
