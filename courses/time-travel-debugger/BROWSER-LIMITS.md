# Browser fallback scope

The course's full Node route supports the supplied Node runtime. checker.html is a bounded fallback for course modules importing only ./vm.mjs or ./disk.mjs. It executes the same public criteria in a module worker and retains source/help/results first. It supports module workers, data-module imports, crypto.subtle and localStorage; the supported execution path is the package-local loopback preview described below. Independent browser acceptance remains separate. Node-only imports and dynamic imports require the Node route.

The storage fallback supplies MemoryDisk, never FileDisk or a real persistent directory. Its CourseBuffer supports alloc/from/concat/isBuffer/byteLength; array indexing/iteration/subarray; read/writeUInt8, UInt16BE and UInt32BE (Uint aliases too); copy, equals, write, toJSON; and UTF-8, hex and ASCII conversion. It is not full Node Buffer. Unsupported import/encoding and detected missing-method execution are reported as execution errors, not a pass. Other runtime differences may need a Node rerun; a browser failure alone is not proof that a Node-valid implementation violates the storage contract. Real file reopen, synchronization and CLI exports must be checked with Node.

Earlier-layer source is explicit optional assistance. A new assisted draft preserves all older drafts and attempts. At stage07 the provided complete earlier tool is for practice; it cannot be claimed as learner-owned engine/debugger implementation. The capstone program/client, experiments and reasoning must be the learner's work. The cumulative own-code path remains available. Neither route certifies mastery or human learning.

This is a concrete platform-scope decision for independent review, not an assertion that arbitrary Node code runs in every browser. No staff, paid model or account is required.

## Supported launch and file-origin limit

Run `node serve.mjs` in the extracted directory and open `http://127.0.0.1:8128/checker.html`. Use `node serve.mjs --port 0` if you need an available local port and open the printed URL. Keep the server open while checking. The helper uses Node built-ins, binds only 127.0.0.1, accepts GET/HEAD only, snapshots a fixed learner reader/checker/SVG allowlist at startup, rejects path traversal and symlinked assets, and serves no project/author/review directory. Restart it after changing course assets. It needs no install, internet connection or security-setting change.

The tested Chromium direct-file route opened the editor but emitted an opaque module-worker error for both unfinished and complete controls. No browser-internal cause is claimed. File pages therefore show an actionable notice and disable checks before hashing or worker creation. Source/history export remains usable. Browser storage is per origin, so changing a port or moving from file to loopback does not silently migrate old attempts; keep the old JSON/source exports and declare the transition in a new draft. Saved old results are never reinterpreted as current checks.
