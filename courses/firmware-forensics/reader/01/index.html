Read the format before the values

EDUFW1 is a teaching format: a 20-byte header, then one 80-byte table entry per component, then payload bytes. A byte offset counts from the start of the file; a size counts how many bytes belong to a range. Endianness specifies how multiple bytes encode an integer. The supplied format uses little endian.

A table entry claims that a payload occupies a range. Establish that the whole table exists before reading its first entry. Compute table_end = 20 + count × 80 and compare it with the actual buffer length. The header also declares a total length; compare that claim with the bytes actually received. Slicing a Python byte string past its end silently returns fewer bytes, so successful slicing does not prove the range was present.

For a worked case with two entries, table_end is 180. In a 192-byte file, a payload at offset 180 with size 12 fits exactly. Size 13 asks for a byte the file does not contain. Raise the supplied FormatError for bad structure; reserve TypeError for a caller passing something other than bytes.

0 ── header (20 bytes) ── 20
20 ── table (count × 80) ── table_end
table_end ── payload ranges ── file_length

Give every payload byte one owner

Two ranges may each fit and still overlap. Sort their intervals, then walk a cursor from table_end. Each interval must begin at the cursor; advance by its size and finish exactly at the file length. A byte-coverage approach is also valid. Preserve table order when constructing the container, even when payloads appear in a different physical order.

For example, intervals [180,184) and [184,192) have lengths 4 and 8. They cover twelve bytes exactly once. [180,185) and [184,192) share byte 184. A range beginning at 185 would instead leave a gap. Labels must be unique safe identifiers, not filesystem paths, and padding after their first NUL must contain only zeros.
