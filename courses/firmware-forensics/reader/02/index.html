Measure first, then join by identity

A component inventory records name, kind, version, offset, size, the digest declared in the table, the digest computed from payload bytes and whether the two agree. A SHA-256 digest is a fixed-size value computed from bytes. It is useful for comparing byte identity; it does not name the person who supplied those bytes.

Compute from each component payload, then sort inventory rows by name. Keep inconsistent rows: a mismatch is evidence. Join the inventory to manifest components by name. If two arrays have different orders, matching by array position pairs unrelated things. A worked pair named config and loader remains that pair after the manifest list is reversed.

Implement component_inventory without reparsing container.data. The checker can give it a valid component object whose original container bytes are unavailable. This separates the inventory responsibility from layout parsing.

Order a graph without inventing a boot trace

A dependency edge says that a named component requires another named component. The declared graph is complete only when every target exists. It is acyclic only when no chain returns to a node already on that chain. A shared dependency reached from two branches is not automatically a cycle.

To check one path, keep an active set of names whose dependencies you are visiting, and a done set of names whose dependencies you have finished. Suppose loader requires runtime and config, and both require table. Visit loader, runtime and table: all three are active. Table has no dependencies, so move it to done, then move runtime to done. While visiting config, you reach table again. Table is done, not active, so this shared dependency creates no cycle. If table instead required loader, reaching the still-active loader would close a cycle. Start another traversal from every name not yet done so disconnected cycles are checked too.

Suppose loader requires runtime and config, runtime requires table, and config and table require nothing. One valid order is table, runtime, config, loader. Another is config, table, runtime, loader. Your map_dependencies must allow both. Missing targets and cycles can coexist; report both instead of letting the first error hide the other.

This order follows declarations. Nothing in this course boots the file or observes a physical loader. When you later investigate a release, keep “declared dependency” separate from “observed execution”.
