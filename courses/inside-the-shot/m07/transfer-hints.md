# Transfer hints — save a prediction first

Opening this page makes the current case assisted practice. Keep the earlier prediction unchanged. A later claim of independent transfer needs another case whose guidance and answer you have not seen.

Use `transfer-hint-1`, `transfer-hint-2` or `transfer-hint-3` with details. A baseline hint label does not identify transfer help.

## Hint 1 — intermediate and published state

Compare the final event snapshot with `final` on the same input in both executables. A trace can describe provisional work. One matching accepted-only input cannot settle what happens after rejection.

## Hint 2 — publication point

In replay, locate the copy from working state to the caller's state. Follow the mode flag and accumulated acceptance information to that copy. Do event snapshots happen before or after the decision? Test a rejection in the middle, not only at the end.

## Hint 3 — challenge an overly broad repair

If your transfer model always returns the initial state, challenge it with an all-accepted file. If it stops at the first rejection, challenge it with a later accepted entry and inspect the event count. Test an empty file as a boundary. These controls distinguish a transaction decision from “no work happened.”
