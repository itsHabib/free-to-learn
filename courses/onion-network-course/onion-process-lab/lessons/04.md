# 4. Write the relay server's behavior

This is the main new implementation task. A child process invokes your `async handleCell(state, packet, io)` for each incoming cell. Your code must decide whether to accept it, which local operation to call, and what to return upstream.

Implement these decisions in order:

1. Authenticate and open one layer with the local forward key.
2. Validate the established successor and presence of a body.
3. Reject a previously accepted sequence; record a new sequence synchronously.
4. Observe metadata, then await either the configured next relay or the archive at the exit.
5. Add this relay's backward layer around the resulting body.

The contract gives `io.forward`, `io.archive` and `io.observe`; each has a different role. Calling the archive at an entry is an error, not a shortcut. Your code is executing separately inside every process, so no shared in-memory route traversal is needed.

**Predict the concurrency bug:** Suppose requests A and B carry the same authentic packet. A checks the replay set, then waits for the next relay. B arrives during that wait. What happens if A adds its sequence only after receiving the reply? Write a six-step timeline. Place the state mutation where the two requests cannot both pass.

Implement `unwrapReply` at the client. The exit returns the innermost backward layer; each preceding relay adds another layer. The client opens entry-to-exit. Bind every layer to the caller's expected sequence, including inner layers.
