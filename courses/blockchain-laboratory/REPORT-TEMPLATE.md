# Partition incident report

## Before running

Record date, source hash if available, prior assistance and the exact scenario version. Predict selected history, committed balances/nonces, rejected claims, stale-proof/certificate results and retained candidate order. Explain the rules used; do not replace this section after observing output.

## Observed trace

Link the attempt receipt. Quote concrete event labels and state fields. Separate committed state from candidate transactions. Distinguish live-pool behavior from rebuilding with explicitly retained input.

## Mismatches and repairs

For each mismatch preserve the original prediction, observed result, diagnosis, code or reasoning repair, and a fresh receipt. “No mismatch” requires a concrete comparison, not just a green exit.

## Assumptions and counterexample

State fixed membership, fault bound, non-equivocation scope, finite delivery and root authority assumptions. Provide one changed network/adversary condition with a step-by-step counterexample. Distinguish safety from liveness and a fixed-height certificate from a complete consensus protocol.

## Review

Apply the five COURSE.md rubric dimensions separately. Mark reasoning not yet reviewed if no reviewer has evaluated it. Record browser/native/live-network checks as NOT RUN unless actually performed.
