# Capstone author and integration notes

The new resource rule is independent of the existing Courier movement and scoring rules. It uses an owned local HTTP adapter with real requests. `policy.mjs` exports synchronous `repair(state,actorId,{requestId,stationId}) -> {reason,receipt,state}`. `state.mjs` defines the validated initial state and two-station configuration. Policy decision order and fields are pinned in `prompt.json` and `LEARNER.md`.

Learner preparation includes only `template.mjs` renamed to `capstone/policy.mjs`, `scenario-template.mjs` renamed to `capstone/scenario.mjs`, `client.mjs`, the exact prompt, learner guide and response template. Never copy `policy.mjs`, `author-scenario.mjs`, controls or fixtures as learner source. The source is an actual two-file exercise; written responses remain separate and ungraded.

Shared-runner extension required (owned by integration): descriptor fields `scenario:'capstone/scenario.mjs'`, `scenarioTemplate:'capstone/scenario-template.mjs'`, `client:'capstone/client.mjs'`; scaffold the scenario template and client; require captured policy and scenario; import only the captured policy in the core worker and call `fixtures.assess({...policyModule,policyPath,scenarioPath})`. Both paths must be absolute paths inside the captured execution tree. Do not import the scenario in the core worker. Preserve hashes and provenance for both sources and any captured relative helpers; verify the supplied client remains unchanged. Existing single-file descriptors continue unchanged. Prompt version 4 clarifies response-first assertions and incomplete-check evidence; version 3 added the expanded behavioral panel and removed the former assertion-dataflow claim; existing frozen prompts/attempts are not rewritten.

APIs:

- `server.mjs`: `createRepairServer({policy=repair,requestAdapter=adaptRequest}={})` provides `base,moveActor,snapshot,record,observation,activity,close`; `withRepairServer(exercise,options)` always closes it. It binds ephemeral loopback only. `moveActor(id,{x,y})` is a direct owner control limited to integer coordinates within ±10000; no HTTP route sets position or resources. `snapshot()` and `record()` return detached copies. Owner-only response observations match opaque response IDs to actual returned state; activity counts state reads and repair requests. Trace entries omit transport tokens. Policy application is synchronous between request-body completion and state commit; no async policy is supported.
- `adaptRequest(state,actorId,body) -> {state,request}` validates exact two-field bodies with 1–40 character IDs using letters, digits, underscore or hyphen. Adapter injection exists only for the author calibration that accepts forbidden claims.
- `client.mjs`: `request(base,path,options)`, `session(base)`, `state(base,token)`, `submit(base,token,body)` are learner-safe HTTP plumbing. Only plain `http://127.0.0.1:<port>` origins are accepted. Network/runtime exceptions are distinct from assertion failures.
- `fixtures.mjs`: `cases()` returns independently keyed pure cases, including two actors using the same ID and an independent receipt capacity; `assessPolicy(candidate)` checks just the policy. `runScenario(scenarioPath,{variant='reference',policyPath,timeout=1000,deadline})` returns `{status,activity,trace,traceDropped,error?,exit}` after a fresh child process closes. Named variants come from the immutable control list; `submitted` imports the supplied absolute policy path. Async `assess({repair,policyPath,scenarioPath})` checks the submitted pair, two correct controls and thirteen wrong variants. Its absolute 8-second whole-panel deadline also bounds each active child's timer and reaps that child before proceeding. These limits constrain the teaching runner and make no production performance claim. Failure details preserve expected, actual and a teaching pointer.
- `scenario-worker.mjs` is a trusted owner module. Each worker imports a fresh captured scenario/module graph and hosts one loopback server. It accepts only genuine `assert.AssertionError` failures, requires a repair and a state read from completed successful runs, and clears the variant/path arguments before importing learner code. The full panel establishes finite behavioral discrimination; it does not prove assertion dataflow. Strings-only plus incidental debug reads misses three isolated resource controls. Native assertion imports, callable assertions, JSON, sorting and cloning are unmodified, and assertion order has no grading significance. Workers share the core worker process group and exit on parent IPC disconnect; the parent owns group cleanup after every outcome. Self-detaching descendants remain outside that boundary. This is not an OS sandbox.
- `runScenario` preserves the first 4096 output bytes and native expected/actual assertion evidence. Timeout, worker exit without a result, output overflow and panel-budget exhaustion are runner failures. `assess` throws `ScenarioRunnerError` so the core runner records an incomplete check rather than a completed learner behavior result. Learner code can cause a timeout; this verdict does not diagnose infrastructure. The error retains completed criteria and bounded per-variant diagnostics under `input`. Neither runtime nor runner failures detect wrong variants.
- `author-cold-clone-scenario.mjs` is an unchanged, authorized cold-learner source snapshot retained only as an author regression fixture, never a prepared learner solution.
- `controls.mjs`: two independently structured correct policies and fifteen wrong policies, of which twelve have reachable HTTP differences from the declared initial session. Partial-top-up, input-mutation and returned-alias controls are pure-fixture checks. An additional adapter control accepts client claims. Isolated wrong controls add only two energy, alter only the receipt balance, or debit on a range refusal. `author-scenario.mjs` is a completed author-only calibration scenario.

Sessions begin at energy 4 and credits 6. Repairs cost 2, add up to 3 energy and cap at 10. The radius is 400 mm and capacity is two successful receipts per actor. Bound exhaustion refuses new IDs without eviction; old retries are still resolved before other checks. HTTP 200 returns rule decisions, 400 rejects a dedicated `RequestRejection` from malformed bodies, and 401 rejects missing/unknown session tokens. A policy exception returns 500 `policy-failure` and its error name; it does not become a malformed-request error or commit state. At most eight sessions, 256 HTTP requests and 4096 request-body bytes are accepted per server run. This is not durable storage, a production authorization service or an OS sandbox.
