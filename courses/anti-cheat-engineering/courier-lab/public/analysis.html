07 / A FINDING NEEDS A DENOMINATOR

One alarming replay cannot estimate a detector.

A detector flags a case for review. A label records what the test author knows about that case. Here positive means a synthetic client repeatedly sent invalid actions. A declared legal automation client is negative; its automation metadata is not passed to the classifier. These labels do not establish human intent. A true positive is a labelled-positive case that is flagged; a false positive is a labelled-negative case that is flagged. Missed positives are false negatives. Correctly unflagged negatives are true negatives.

Precision

TP / (TP + FP)
Of flagged cases, how many have the positive label?

Recall

TP / (TP + FN)
Of positive cases, how many were flagged?

False-positive rate

FP / (FP + TN)
Of negative cases, how many were flagged?

A zero denominator gives no estimate: report null, not an invented zero. Count each case once. Repeated observations from one case are not additional independent people.

09 / DATA HAS A PURPOSE AND A COST
Keep enough to answer a named question.
Retention is the rule for how long data stays available. The denial-event export in this lesson keeps only tick, actor identifier, reason and squared distance. That is enough for this detector's window calculation; it is not enough to replay the whole game. The richer checkpoint/window format from module 6 has a different purpose.
Actor identifiers still link behavior inside a run. Removing a capability token or a device field does not make the remaining events anonymous. An age limit and a record-count limit answer different questions: how old can an event be, and how much can the store hold?

Make the limits executable.

Implement retention/policy.mjs in the printed workspace. Filter by the stated age boundary, keep the newest permitted count and project to exactly the allowed fields. Preserve input order and leave the input unchanged.
npm run core:check -- --assistance "none"
From the reference project, use your completed self-contained policy to compare two settings: Export a denial-event file, inspect its fields, then delete that export using the supplied command and verify that the path is gone. This deletes that file only; copied files, earlier reports and original records are separate artifacts.
npm run retention:measure -- /path/to/policy.mjs artifacts/measure-01.json 4095:512:64 4095:128:16 --warmup 5 --samples 20
npm run retention:export -- /path/to/policy.mjs artifacts/denials-01.json artifacts/receipt-01.json 256 128
npm run retention:delete -- artifacts/receipt-01.json artifacts/deleted-01.json
Every output must be a fresh path; use a new numbered path for each revision. The export source is a named synthetic workload held in memory. These commands run your JavaScript locally; they are not a security sandbox.
Keep settings, measured counts, byte lengths and runtime metadata with your explanation. State the investigation this export supports and one question that its reduced fields or shorter history can no longer answer. Do not put real player identifiers or external credentials in this teaching corpus.
