04 / ONE SERVER CLOCK

Late delivery does not move the past.

A server tick advances the simulation once. A network callback delivers a message; it does not necessarily advance a tick. This model processes 50 ms ticks and limits catch-up after a long pause. The accepted input receives its expiry from the server's current tick, not from a client timestamp.

Input admitted at tick T remains active through T+4. At T+5 it stops unless a newer input renewed it. An equal or older sequence does not renew the expiry. A disconnected browser may stop delivering messages while its existing server actor continues until expiry. Resuming that session preserves the actor; a new session creates a different actor.

10 / A RELEASE IS MORE THAN ITS CODE
Choose a compatible recovery point.
A configuration supplies values such as the allowed interaction radius. A state schema specifies the shape of saved data. The trial changes the radius from 250 to 100 mm and writes a new state envelope. A legal boundary pickup now fails. Restoring the old code while retaining the new envelope cannot restore the old state.
Your selector must return an existing, compatible package/configuration/snapshot tuple. Follow the declared target release, verify configuration identity and select the newest compatible snapshot. Do not invent a migration or silently substitute another release. A hash identifies bytes; it does not authenticate who approved them.

A real service needs a recovery epoch or an external acknowledgement floor before accepting retries. A new pickup after restore does not reimburse a lost delivery or prove production rollback safety.

11 / BUILD AND INDEPENDENTLY CHALLENGE
A repair has a price. A retry is not another purchase.
Build a separate repair-station extension to the owned arena. The server owns position, credits and energy. A request contains only requestId and stationId. At a distance of at most 400 mm, a repair costs two credits and restores three energy, capped at ten. The initial balance is six credits and four energy.
The first successful ID records a receipt. A retry of that ID for the same station returns the original receipt, even after movement, without charging again. A conflicting station refuses. Failed requests reserve no ID. When the two-receipt capacity is full, new IDs refuse instead of evicting old receipts and reopening a double-charge path.
Write an explanation before using the worked example. Identify the authority boundary, give a concrete double-charge counterexample, explain the receipt-capacity tradeoff and propose an independent regression test. Transfer to a different resource with a delayed completion and decide when its receipt becomes final.
